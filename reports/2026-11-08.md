## 오늘의 핵심 AI 뉴스 요약

### 1. Google Gen AI SDK v3.0.0, API 기본값과 런타임 요구사항 변경
* **카테고리:** AI 플랫폼 / SDK
* **주요 내용:**
  - JavaScript와 Python SDK v3.0.0이 Gemini Developer API의 기본 버전을 `v1beta`에서 `v1`로 변경했다.
  - JavaScript SDK는 Node.js 22 이상을 요구하고, Python SDK는 기본 HTTP 클라이언트를 `httpx`에서 `httpx2`로 바꿨다.
  - `CodeExecutionResultStep.result`가 단일 문자열이 아닌 유니온 타입으로 변경됐으며, API 버전은 환경 변수나 코드에서 명시적으로 지정할 수 있다.
* **엔지니어 관점 포인트:**
  - 이번 업데이트는 일반적인 의존성 패치가 아니라 호환성 마이그레이션이다. 업그레이드 전 Node·Python 런타임, 모델 별칭, API 버전, HTTP 클라이언트, 코드 실행 결과 파싱을 함께 점검해야 한다.
  - Node 20 또는 기존 `v1beta` 동작을 유지해야 하는 서비스는 문서화된 버전 고정·환경 변수 설정을 먼저 적용하고 단계적으로 전환하는 편이 안전하다.
* **관련 링크:** [Google Gen AI JavaScript SDK v3.0.0](https://github.com/googleapis/js-genai/releases/tag/v3.0.0), [Google Gen AI Python SDK releases](https://github.com/googleapis/python-genai/releases)

### 2. AWS Bedrock, 100만 토큰 컨텍스트의 Kimi K3.1 Pro Highspeed 제공
* **카테고리:** LLM 플랫폼 / 클라우드 API
* **주요 내용:**
  - AWS가 Amazon Bedrock에서 Moonshot AI의 Kimi K3.1 Pro Highspeed를 제공하기 시작했다.
  - AWS는 이 모델이 에이전트 코딩과 문서 처리에 적합하고, 네이티브 멀티모달 입력과 100만 토큰 컨텍스트, 프롬프트 캐싱을 지원한다고 설명한다.
  - Bedrock에서는 Responses, Chat Completions, Converse, InvokeModel 인터페이스와 Global·US·India 교차 리전 추론 프로필을 제공한다.
* **엔지니어 관점 포인트:**
  - 이미 Bedrock을 사용하는 팀은 별도 호스팅 없이 장문 문서·코딩 에이전트 실험을 시작할 수 있지만, 교차 리전 프로필 선택이 데이터 거버넌스와 라우팅 설계에 직접 영향을 준다.
  - 가격과 캐시 요금은 리전·서비스 티어·캐시 적중률에 따라 달라지므로, 실제 프롬프트와 추론 프로필을 고정한 비용·품질 벤치마크가 필요하다. 공식 자료는 가용성과 가격을 제시하지만 경쟁 모델 대비 품질 우위까지 입증하지는 않는다.
* **관련 링크:** [AWS Bedrock Kimi K3.1 Pro Highspeed 안내](https://aws.amazon.com/about-aws/whats-new/2026/11/moonshot-ai-kimi-k3-1-pro-on-amazon-bedrock/), [AWS Bedrock 모델 카드](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3-1-highspeed.html)

### 3. Microsoft Agent Framework 1.25.0, MCP 승인과 사용자 범위 격리 강화
* **카테고리:** Agentic AI / 보안 / 프레임워크
* **주요 내용:**
  - MCP 도구 탐색에 승인 정책을 적용하고, Foundry Toolbox의 승인 메타데이터와 도구명·읽기 전용 필터·호출자별 재정의를 지원한다.
  - 보존된 도구의 정책을 새로 고칠 수 있으며, 탐색은 기본적으로 100페이지·1,000개 카탈로그 항목·30초 요청 시간 제한을 둔다. 갱신 실패 시에는 마지막 완전한 카탈로그 스냅샷을 유지한다.
  - 실행 중인 워크플로우·실행기·세션을 하나의 권한 범위에 묶어 다른 범위의 실행을 모델 호출 전에 거부한다. Python 3.10은 더 이상 지원하지 않아 3.11 이상이 필요하다.
* **엔지니어 관점 포인트:**
  - MCP 카탈로그는 단순한 검색 결과가 아니라 권한 정책의 입력으로 다뤄야 한다. 도구 승인, 읽기 전용 여부, 호출자 범위를 배포 설정과 함께 테스트하는 것이 핵심이다.
  - 여러 사용자를 서비스하는 기존 애플리케이션은 호출마다 워크플로우·실행기·세션을 생성하는 구조를 검토해야 한다. 릴리스 노트는 단일 사용자일 때만 `single_user=True`를 사용하도록 안내한다.
* **관련 링크:** [Microsoft Agent Framework Python 1.25.0](https://github.com/microsoft/agent-framework/releases/tag/python-1.25.0)

### 4. OpenCode v2.2.6, MCP 공유와 격리된 스크립트 실행 추가
* **카테고리:** 오픈소스 / 개발자 도구 / Agentic AI
* **주요 내용:**
  - 같은 설정을 사용하는 프로젝트 사이에서 MCP 연결을 공유하는 `pool: true` 옵션을 추가했다.
  - `opencode run -w` 또는 `--worktree`로 스크립트 작업을 새 Git worktree에서 실행하고, `--archived`로 자동화 세션을 일반 목록에서 분리할 수 있다.
  - 비대화형 `run`이 셸 명령, 하위 에이전트, 이미지 작업의 완료까지 기다리도록 바뀌었고, 파일·미디어 전달은 샌드박스 다운로드와 리다이렉트 권한 검사를 거친다.
* **엔지니어 관점 포인트:**
  - MCP 프로세스 중복과 병렬 작업 간 파일 충돌을 줄일 수 있는 실행 계층 업데이트다. 다만 `run`이 개발 서버나 파일 감시자가 끝날 때까지 종료되지 않을 수 있어 CI에는 명시적 타임아웃이 필요하다.
  - 기존 자동화가 모델의 최종 텍스트 출력 직후 프로세스가 끝난다고 가정했다면, 이번 버전으로 수명주기 회귀 테스트를 먼저 수행해야 한다.
* **관련 링크:** [OpenCode v2.2.6 release](https://github.com/anomalyco/opencode/releases/tag/v2.2.6)

### 5. Google ADK Python v2.14.0, 실행 환경·A2A·평가 모듈 안정화
* **카테고리:** Agentic AI / 오픈소스 프레임워크 / 평가
* **주요 내용:**
  - `BaseEnvironment`, 로컬·Daytona·E2B 환경, 환경 도구 모음, A2A, 평가, 핵심 런타임 모듈을 실험 단계에서 안정 API로 승격했다.
  - `adk eval --num_runs`와 `--parallelism`으로 다중 평가를 병렬 실행할 수 있고, 도구 인자 비교에 정확 일치·대소문자 무시·수치 허용 오차·LLM 기반 의미 비교 모드를 제공한다.
  - 릴리스 노트에는 한 30노드·200턴 워크플로우에서 23% 빠른 실행과 9% 낮은 최대 메모리 사용량이 보고됐지만, 하드웨어·모델·워크로드·통계 방법은 공개되지 않았다.
* **엔지니어 관점 포인트:**
  - 샌드박스 실행, A2A 연동, 반복 평가를 실험용 코드에서 운영 가능한 표면으로 옮기려는 팀에 의미 있는 경계선이다. 특히 병렬 평가와 도구 인자 매칭은 에이전트 회귀 테스트를 자동화하기 쉽게 만든다.
  - Enum 도구 인자 타입, 세션 생성 옵션, 환경 모드의 스크립트 실행 인자에 breaking change가 있으므로 업그레이드 전 호출부를 점검해야 한다. 성능 수치는 프로젝트 단일 측정이므로 일반적인 개선으로 확대 해석하면 안 된다.
* **관련 링크:** [Google ADK Python v2.14.0](https://github.com/google/adk-python/releases/tag/v2.14.0)
