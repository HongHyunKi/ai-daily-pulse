### 1. Anthropic, MCP 서버에 Skills·Tasks·Elicitation 확장
* **카테고리:** Agentic AI / MCP / Developer Tool
* **주요 내용:**
  - Anthropic이 11월 24일 Claude와 Claude Code에서 MCP 서버가 도구와 함께 작업 지침을 배포하는 `Skills over MCP` 공개 베타를 시작했다.
  - MCP 서버는 이제 오래 걸리는 작업을 백그라운드에서 실행하는 Tasks와, 비용 승인·삭제 확인처럼 진행 중 사용자 입력을 받는 Elicitation을 정식 지원한다.
  - 파일을 컨텍스트 창에 넣지 않고 MCP 서버로 주고받는 File Uploads도 곧 제공될 예정이다.
  - Skills는 필요한 시점에만 로드되고 서버와 함께 갱신되며, 해당 기능은 공개 MCP 확장으로 안내됐다.
* **엔지니어 관점 포인트:**
  - MCP 통합이 단순한 함수 호출을 넘어 장기 실행·승인·도메인별 플레이북을 포함하는 작업 단위로 확장되고 있다.
  - 서버가 내려주는 지침이 실행 권한과 결합될 수 있으므로, 허용할 Skill·도구·리소스를 분리하고 파일·삭제·결제 같은 경계에는 명시적 승인을 남겨야 한다.
* **관련 링크:** [Source Link](https://claude.com/resources/articles/skills-over-mcp-tasks-and-more)

### 2. Google Workspace MCP 서버 다수 GA, 표준 쿼터와 비용 관리 시작
* **카테고리:** Developer Tool / Agentic AI / API Platform
* **주요 내용:**
  - Google이 11월 24일 Gmail, Calendar, Drive, Docs, Sheets, Slides, Chat, Tasks용 Workspace MCP 서버의 일반 제공 범위를 확대했다.
  - Gmail·Chat·Calendar·Docs·Drive·Sheets 등은 AI 에이전트가 검색·읽기·작성·수정·메시지 전송 같은 작업을 수행할 수 있으며, MCP form elicitation 기반 사용자 승인을 지원한다.
  - Standard Tier는 GA MCP 서버별 프로젝트당 하루 5,000 요청까지 무료로 제공되고, 더 높은 한도는 결제 계정이 연결된 Scaled Tier가 필요하다.
  - Google은 쿼터 대시보드를 함께 제공하며, MCP 요청은 하나의 도구 호출이 여러 API 요청으로 계산될 수 있다고 명시했다.
* **엔지니어 관점 포인트:**
  - Workspace를 에이전트의 표준 업무 도구로 연결하기 쉬워졌지만, 읽기와 쓰기 권한·승인 흐름·프로젝트별 쿼터를 기능 출시 전에 설계해야 한다.
  - Standard Tier의 5,000건 제한과 2027년 예정된 MCP 비용·REST API 정책 변경을 고려해 호출 집계, 재시도, 캐시, 예산 알림을 준비할 필요가 있다.
* **관련 링크:** [Source Link](https://developers.google.com/workspace/release-notes)

### 3. Google Agent Retrieval, 파일·동영상 검색 파이프라인을 관리형으로 제공
* **카테고리:** RAG / Developer Tool / Agentic AI
* **주요 내용:**
  - Google Developers Blog가 11월 24일 Agent Retrieval의 관리형 ingestion과 `SearchDocuments`를 공개 프리뷰로 소개했다.
  - Cloud Storage의 PDF, Office 문서, 텍스트, 동영상을 별도 파서·청킹·임베딩 파이프라인 없이 데이터 스토어에 연결할 수 있다.
  - `SearchDocuments`는 하이브리드 검색, 메타데이터 필터, 선택적 재순위를 지원하고 문서의 페이지 범위나 영상의 시간 구간을 함께 반환한다.
  - 동영상은 시각 정보와 음성 트랙을 함께 검색할 수 있으며, 프리뷰 기간에는 `us-east4`와 `europe-west4`가 지원된다.
* **엔지니어 관점 포인트:**
  - 인하우스 RAG의 반복적인 ingestion 코드를 줄이고 출처가 있는 검색 결과를 에이전트 도구로 바로 연결할 수 있다.
  - 아직 `v1beta` 공개 프리뷰이고 Python SDK 지원은 예정 사항이므로, 프로덕션 전환 전에는 리전 제한·비용·삭제 시 backing Collection 처리·검색 품질을 검증해야 한다.
* **관련 링크:** [Source Link](https://developers.googleblog.com/from-files-to-cited-answers-in-one-api-call-managed-ingestion-and-searchdocuments-in-agent-retrieval/)

### 4. JetBrains Mellum2.1 Instruct, 빠른 로컬 코딩 에이전트용 오픈 모델 공개
* **카테고리:** Open Source / LLM / Coding Agent
* **주요 내용:**
  - JetBrains가 11월 25일 Mellum2.1 Thinking의 직접 응답형 형제 모델인 Mellum2.1 Instruct를 Apache 2.0 라이선스로 공개했다.
  - 12B 전체·2.5B 활성 파라미터의 MoE 모델이며, 서브에이전트·도구 루프·간단한 코드 수정처럼 긴 추론이 필요하지 않은 작업을 겨냥한다.
  - Hugging Face와 GGUF 배포본, Multi-Token Prediction 헤드를 제공하며, JetBrains는 Thinking 모델보다 에이전트 코딩 작업에서 생성 토큰이 약 절반이라고 보고했다.
  - SWE-bench와 속도 수치는 JetBrains 자체 평가이므로 독립적인 재현 결과로 보기는 어렵다.
* **엔지니어 관점 포인트:**
  - 계획·디버깅은 강한 추론 모델에 맡기고 반복적인 편집·명령·분류는 로컬 Instruct 모델로 처리하는 계층형 에이전트 구성을 시험할 수 있다.
  - 실제 도입 시에는 모델 카드의 Transformers/vLLM 요구사항, tool calling 호환성, GGUF 양자화 품질, 저장소 코드의 데이터 경계를 먼저 검증해야 한다.
* **관련 링크:** [Source Link](https://huggingface.co/JetBrains/Mellum2.1-12B-A2.5B-Instruct)

### 5. llama.cpp b12732, 비동기 입력 복사 경로를 포함한 최신 pre-release
* **카테고리:** Open Source / LLM Inference
* **주요 내용:**
  - llama.cpp가 11월 25일 21:51 UTC에 b12732 pre-release를 공개했다.
  - CUDA에서 선택적으로 입력을 비동기 복사하고 단일 동기화로 처리하는 `fast_async_host_input` 경로를 추가했으며, 파이프라인 병렬 실행과 그래프 재사용 관련 동작을 함께 조정했다.
  - 테스트에는 비동기 계산 뒤 스케줄러 입력을 덮어쓸 수 있는지 확인하는 검증이 포함됐다.
  - 안정 릴리스가 아닌 pre-release이므로 모든 백엔드가 같은 이점을 얻는다고 단정할 수 없다.
* **엔지니어 관점 포인트:**
  - CUDA 기반 로컬·서빙 환경에서 입력 전송과 추론 겹치기를 실험할 수 있어, 긴 컨텍스트나 다중 요청 처리의 병목을 줄일 가능성이 있다.
  - 운영 환경에 바로 고정하기보다 사용하는 GPU·백엔드·파이프라인 병렬 설정별로 지연시간, 메모리, 결과 안정성을 비교하고 회귀 시 이전 태그로 되돌릴 수 있게 해야 한다.
* **관련 링크:** [Source Link](https://github.com/ggml-org/llama.cpp/releases/tag/b12732)
