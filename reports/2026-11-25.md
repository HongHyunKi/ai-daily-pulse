## 오늘의 핵심 AI 뉴스 요약

### 1. OpenAI Agents SDK v0.26.0, 샌드박스와 가드레일을 강화
* **카테고리:** 에이전트 SDK / 실행 보안
* **주요 내용:**
  - OpenAI Agents SDK Python v0.26.0이 11월 24일 정식 릴리스됐다.
  - Docker 저장소 마운트, 커스텀 Realtime tracing, 로컬 이미지 사용 방식에 변경이 있어 일부는 마이그레이션이 필요하다.
  - TAR 경로 검증, Docker 마운트 권한 제한, 입력 가드레일 거부 뒤 대기 중인 함수 도구 중단, Realtime 가드레일 검사 시점 조정이 포함됐다.
  - MCP에서는 호출별 명시적 메타데이터가 탐색 기본값보다 우선한다.
* **엔지니어 관점 포인트:**
  - 단순 패치 업그레이드로 보지 말고 Docker 세션 매니페스트, `TraceProvider`, 실험적 Codex 로컬 이미지 호출을 먼저 점검해야 한다.
  - 보안·신뢰성 개선의 실제 효과는 외부 벤치마크가 아니라 릴리스 노트에 근거한 변경 사항이므로, 기존 에이전트 회귀 테스트로 확인해야 한다.
* **관련 링크:** [Source Link](https://github.com/openai/openai-agents-python/releases/tag/v0.26.0)

### 2. OpenAI, API에 헬스케어 모델 구성 공개
* **카테고리:** 의료 AI / API 플랫폼
* **주요 내용:**
  - OpenAI가 11월 24일 API 조직에서 헬스케어용 모델 구성을 사용할 수 있다고 문서화했다.
  - Responses API에서 예시 모델 ID `gpt-6.2-astra-healthcare`를 사용할 수 있고, 웹 검색을 켜면 전용 헬스케어 검색 인덱스를 활용한다.
  - 이는 ChatGPT for Healthcare나 ChatGPT Enterprise 전용 기능이 아니라 API 조직을 대상으로 한 가용성 변경이다.
  - OpenAI 문서상 별도 GA/preview 표시는 없으며, 검색 결과와 답변은 개발자가 검토해야 한다.
* **엔지니어 관점 포인트:**
  - 의료 워크플로의 근거 검색·요약을 API로 프로토타이핑할 수 있지만, 모델 구성 자체가 규제 준수나 PHI 처리 권한을 부여하지는 않는다.
  - 보호 건강정보(PHI)를 처리하려면 적용 가능한 BAA와 계정·도구 요건을 별도로 충족해야 하므로, 배포 전에 법무·임상 거버넌스와 출처 검토 절차를 마련해야 한다.
* **관련 링크:** [Source Link](https://help.openai.com/en/articles/20001656-healthcare-model-configurations-in-the-openai-api)

### 3. Hugging Face Transformers v5.24.1, 모델·분산 실행 호환성 패치
* **카테고리:** 오픈소스 모델 프레임워크
* **주요 내용:**
  - Transformers v5.24.1이 11월 25일 01:13 KST에 공개된 안정 패치 릴리스다.
  - remote-code 캐시 이름 변경의 하위 호환성, `modeling_attn_mask_utils` 복원, `past_key_values` 노출, OmniASR CPU 마스크 처리를 수정했다.
  - Llama 4 이미지 출력 오류와 Dory 정적 캐시 문제를 고치고, `tp_plan={}`를 통한 expert parallelism과 PyTorch 2.9의 strided checkpoint 읽기를 보완했다.
* **엔지니어 관점 포인트:**
  - vLLM·커스텀 remote-code 모델·분산 추론을 함께 쓰는 팀에는 기능 추가보다 호환성 측면에서 우선 검토할 가치가 큰 패치다.
  - 캐시와 모델 출력 인터페이스에 닿는 수정이 있으므로, 정확한 버전 고정과 기존 로드·생성 회귀 테스트를 거친 뒤 올리는 편이 안전하다.
* **관련 링크:** [Source Link](https://github.com/huggingface/transformers/releases/tag/v5.24.1)

### 4. Ollama v0.40.18, Metal 추론을 다듬고 JetPack 5 지원 제거
* **카테고리:** 로컬 추론 런타임
* **주요 내용:**
  - Ollama v0.40.18이 11월 24일 13:18 KST에 공개된 안정 릴리스다.
  - Metal에서 Inkling residual mixing을 융합하고, `mlxrunner`에 텐서·모델 설정 헬퍼를 공유하며, llama.cpp b12651을 반영했다.
  - 릴리스 노트는 Inkling 2의 decode·prefill·draft 라운드가 빨라졌다고 설명하지만, 이는 독립 검증되지 않은 유지관리자 주장이다.
  - JetPack 5 지원은 제거됐다.
* **엔지니어 관점 포인트:**
  - Apple Silicon에서 Inkling 2를 돌리는 개발자는 백엔드 개선을 얻을 수 있지만, Jetson 사용자는 JetPack 5 환경을 확인하지 않고 업그레이드하면 안 된다.
  - 로컬 런타임은 모델 품질보다 하드웨어 조합의 회귀가 더 큰 위험이므로, 실제 장치에서 지연시간·메모리·지원 버전을 함께 검증해야 한다.
* **관련 링크:** [Source Link](https://github.com/ollama/ollama/releases/tag/v0.40.18)

* **카테고리:** 코딩 에이전트 / 엔터프라이즈 운영
* **주요 내용:**
  - Claude Code v2.1.331이 11월 24일 06:34 KST에 공개된 immutable 정식 릴리스다.
  - 터미널 세션의 Code Mode가 Amazon Bedrock, Google Cloud Agent Platform, Microsoft Foundry, AWS의 Claude Platform으로 확대됐다.

* **엔지니어 관점 포인트:**
  - 여러 관리형 모델 플랫폼에서 터미널 에이전트 운영 방식을 통일할 수 있지만, OIDC 그룹 추출·프록시 설정·플러그인 매니페스트·MCP 타임아웃을 단계적으로 검증해야 한다.
  - MCP 응답 정지 수정은 릴리스에 명시된 동작 변경이며, 장애 빈도나 운영 개선 폭 자체가 수치로 검증된 것은 아니다.
* **관련 링크:** [Source Link](https://github.com/anthropics/claude-code/releases/tag/v2.1.331)
