## 오늘의 핵심 AI 뉴스 요약

### 1. Google, 코딩 에이전트의 ‘TODO 분산’ 비용을 91만3천 세션으로 분석
* **카테고리:** Agentic AI / Developer Tool
* **주요 내용:**
  - Google이 2026년 11월 6일 공개한 분석에서 91만3천 건이 넘는 코딩 에이전트 세션을 조사했다.
  - 세션의 13%가 `TODO(b/...)` 또는 `FIXME(b/...)` 버그 참조에 노출됐고, 그중 6%는 에이전트가 해당 이슈를 후속 행동으로 이어갔다. 이 후속 행동의 83%는 개발자가 요청하지 않은 작업이었다.
  - 이런 우회 작업은 세션당 단계 70%, 토큰 77%, 대기 시간 105% 증가와 연결됐다. 닫힌 이슈를 쫓는 경우와 열린 이슈로 범위를 넓히는 경우가 모두 확인됐다.
* **엔지니어 관점 포인트:**
  - 오래된 주석과 문서는 사람에게는 참고 정보지만, 에이전트에게는 실행 지시처럼 읽힐 수 있다. 에이전트 도입 팀은 코드 품질 점검에 기능 코드뿐 아니라 오래된 TODO·이슈 링크 정리도 포함해야 한다.
  - 프리서밋 린터나 저장소 스캐너로 종료·폐기된 이슈 참조를 자동 검출하면 토큰 비용과 범위 이탈을 함께 줄일 수 있다.
* **관련 링크:** [Google Developers Blog: Agent Distraction](https://developers.googleblog.com/en/agent-distraction/)

### 2. OpenAI Codex CLI 0.167.0, 에이전트 커맨드 센터와 백엔드 전환 추가
* **카테고리:** Developer Tool / Agentic AI
* **주요 내용:**
  - OpenAI Codex CLI가 11월 6일 0.167.0을 릴리스했다.
  - `codex agents --no-daemon`으로 에이전트 커맨드 센터를 열 수 있고, 세션 선택기에서 읽지 않은 결과를 표시한다.
  - 터미널 세션 선택기에서 연결된 백엔드를 바꿀 때 작성 중인 초안을 유지하며, 지원되는 터미널에서는 로컬 이미지 첨부를 미리 볼 수 있다.
* **엔지니어 관점 포인트:**
  - 이번 릴리스는 모델 자체의 성능보다 여러 작업과 세션을 관리하는 CLI 운영 계층을 강화한 업데이트다. 코딩 에이전트를 병렬로 사용하는 팀은 세션 상태와 미확인 결과를 한곳에서 관리하기 쉬워진다.
  - 백엔드 전환 시 초안 보존은 모델·환경을 바꿔가며 비교하는 개발 루프의 마찰을 낮춘다. 다만 실제 도입 전에는 현재 사용 중인 터미널과 브라우저 연동의 호환성을 확인해야 한다.
* **관련 링크:** [OpenAI Codex 0.167.0 Release](https://github.com/openai/codex/releases/tag/rust-v0.167.0)

### 3. Baidu, 280B/14B 활성 파라미터의 ERNIE 5.5 Flash Base 공개
* **카테고리:** Open Source / LLM
* **주요 내용:**
  - Baidu가 11월 5일 사전학습이 끝난 베이스 체크포인트 ERNIE-5.5-Flash-Base를 Hugging Face에 공개했다.
  - 총 280B 파라미터 중 토큰당 14B를 활성화하는 희소 MoE 모델이며, 33.5T 토큰으로 학습됐다. 학습 컨텍스트는 128K, 파인튜닝·추론 설정은 최대 1M 토큰을 지원한다.
  - FP8과 BF16 가중치를 제공하고, 지시 튜닝 전 체크포인트이므로 도메인 적응·지시 튜닝·RL 연구의 출발점으로 사용할 수 있다.
* **엔지니어 관점 포인트:**
  - 활성 파라미터 수가 작아도 전체 가중치와 KV 캐시를 감당할 메모리는 여전히 크다. ‘14B 모델처럼 가볍다’고 가정하기보다 실제 서빙 하드웨어와 병렬화 비용을 먼저 산정해야 한다.
  - 베이스 모델 공개는 자체 데이터로 후속 학습하려는 팀에 선택지를 넓히지만, 함께 제공된 라이선스가 커스텀 조건이므로 상업 배포·파생 모델 정책을 도입 전에 검토해야 한다.
* **관련 링크:** [Baidu ERNIE-5.5-Flash-Base Model Card](https://huggingface.co/baidu/ERNIE-5.5-Flash-Base)

### 4. Hugging Face, harness별 LoRA 어댑터와 안전 RL 실험 공개
* **카테고리:** Open Source / Agentic AI
* **주요 내용:**
  - Hugging Face가 11월 6일 `pi`, `opencode`, `hermes` 같은 에이전트 harness별로 학습한 LoRA 어댑터 실험을 공개했다.
  - 검증 가능한 코드 작업과 질의응답 환경에서 RL을 수행하고, `safeagents` 프록시가 모델의 도구 호출을 실행 전에 검사하도록 구성했다.
  - 공개된 초기 smoke·held-out 평가에서는 기본 모델보다 도구 호출 수가 줄면서 정확도를 유지하거나 높였다고 보고했지만, 아직 실험 단계의 결과다.
* **엔지니어 관점 포인트:**
  - 같은 기반 모델이라도 도구 목록, 프롬프트, 제어 루프가 다른 harness에 맞춰 정책을 따로 최적화할 수 있다는 방향을 보여준다. 에이전트 로그를 단순 모니터링 데이터가 아니라 평가·학습 자산으로 보는 흐름도 강해지고 있다.
  - 도구 호출을 모델 판단과 분리해 규칙 기반 프록시에서 검사하는 구조는 reward hacking과 위험한 단축 경로를 줄이는 실용적인 방어선이 될 수 있다. 다만 공개 수치가 초기 실험 결과인 만큼 자체 작업셋으로 재현성부터 확인해야 한다.
* **관련 링크:** [Hugging Face: Harness adapters](https://huggingface.co/blog/harness-hub/harness-adapters)

### 5. LangGraph 1.2.20, 인터럽트 식별자와 엄격한 재개 모드 추가
* **카테고리:** Agentic AI / Developer Tool
* **주요 내용:**
  - LangGraph가 11월 5일 1.2.20을 릴리스하고, 하나의 태스크 안에서 각 `interrupt()` 호출에 고유 ID를 부여했다.
  - `strict resume` 모드는 오래된 인터럽트 응답을 거부해, 재시작·재연결 뒤 stale한 사용자 응답이 잘못된 단계에 적용되는 것을 막는다.
  - 관련 SDK와 CLI도 11월 6일 업데이트됐으며, CLI에는 배포 메트릭 명령과 보안 수정이 포함됐다.
* **엔지니어 관점 포인트:**
  - 장시간 실행 에이전트에서 가장 까다로운 문제 중 하나인 중단 후 재개 상태의 일관성을 프레임워크 레벨에서 보강했다. 승인 대기, 사람 검토, 외부 이벤트 콜백이 있는 워크플로우의 오류 범위를 줄일 수 있다.
  - 기존 그래프에서 인터럽트 응답을 저장·재전달하는 코드는 strict 모드 도입 전에 회귀 테스트가 필요하다. 특히 재시도와 재연결 시 어떤 응답이 현재 실행에 속하는지 명시적으로 검증해야 한다.
* **관련 링크:** [LangGraph Releases](https://github.com/langchain-ai/langgraph/releases/tag/1.2.20)
