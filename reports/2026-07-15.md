# Daily AI Pulse: 2026-07-15

## 오늘의 핵심 AI 뉴스 요약

### 1. OpenAI, GPT-5.6 3종 라인업(Sol·Terra·Luna) 공개 배포 시작
**카테고리:** LLM

**주요 내용:**
- OpenAI가 7월 9일부터 GPT-5.6 시리즈의 일반 공개를 시작했다. 코딩·과학·보안 분야에 강점을 둔 플래그십 Sol, GPT-5.5급 성능을 절반 가격에 제공하는 균형형 Terra, 최저 비용의 고속 모델 Luna로 3단계 라인업을 구성했다.
- 가격은 100만 토큰 기준 Sol이 입력 5달러·출력 30달러, Terra가 입력 2.5달러·출력 15달러, Luna가 입력 1달러·출력 6달러다. Cerebras 인프라를 통해 Sol은 초당 750토큰까지 처리 속도를 끌어올렸고, 기존 xhigh 상위 단계인 Max Reasoning Effort와 여러 서브에이전트를 병렬로 조율하는 Ultra Mode가 새로 추가됐다. 같은 주 xAI의 Grok 4.5, Meta의 Muse Spark 1.1도 잇따라 공개되며 프론티어 모델 경쟁이 다시 달아올랐다.

**엔지니어 관점 포인트:**
세 모델로 가격과 성능을 세분화한 구조는 프로덕션 환경에서 태스크 난이도별로 모델을 나눠 쓰는 방식이 사실상 표준이 되고 있음을 보여준다. Ultra Mode의 병렬 서브에이전트 조율 기능은 단일 에이전트 중심으로 짜인 기존 워크플로우에 태스크 분해와 오케스트레이션 로직을 새로 요구하게 될 가능성이 크며, 평균 3일에 한 번꼴로 신모델이 쏟아지는 현재 속도는 특정 모델에 강하게 결합되지 않은 라우터·게이트웨이 아키텍처의 가치를 키우고 있다.

**관련 링크:** [OpenAI - Previewing GPT-5.6 Sol](https://openai.com/index/previewing-gpt-5-6-sol/)

### 2. xAI, 코딩·에이전틱 특화 모델 Grok 4.5 출시
**카테고리:** LLM

**주요 내용:**
- xAI(현재 SpaceXAI로 표기)가 7월 8일 Grok 4.5를 공개했다. 수만 대의 NVIDIA GB300 GPU로 학습했으며 코딩, 에이전틱 툴콜링, 지식노동 작업에 초점을 맞췄다.
- Artificial Analysis Intelligence Index 종합 순위 4위를 기록했고 agentic tool use 부문에서는 1위에 올랐다. SWE-Bench Pro에서는 Opus 4.8 대비 약 4.2배 적은 출력 토큰으로 동일 과제를 해결했다. 컨텍스트 윈도우는 50만 토큰이며, 가격은 100만 토큰당 입력 2달러·출력 6달러로 Cursor 전 플랜에서 바로 사용할 수 있다.

**엔지니어 관점 포인트:**
절대 성능 수치보다 토큰당 효율과 비용이 모델 선택의 실질적 기준으로 옮겨가고 있음을 보여주는 사례다. 벤치마크 격차가 크지 않은 상황에서는 결국 동일 작업을 얼마나 적은 토큰과 비용으로 처리하느냐가 실무 채택을 좌우하게 될 것으로 보인다.

**관련 링크:** [xAI - Introducing Grok 4.5](https://x.ai/news/grok-4-5)

### 3. GitHub Copilot, 첫 오픈웨이트 모델로 Kimi K2.7 Code 정식 탑재
**카테고리:** Open Source / Developer Tool

**주요 내용:**
- GitHub이 7월 1일 Moonshot AI의 오픈웨이트 코딩 모델 Kimi K2.7 Code를 Copilot 모델 피커에 정식 추가했다. 1조 파라미터 규모의 Mixture-of-Experts 구조로 토큰당 활성 파라미터는 320억이며, MIT 라이선스로 전체 가중치가 Hugging Face에 공개되어 있다.
- Hugging Face에 가중치가 올라온 지 19일 만에 Copilot에 통합됐다. VS Code, Visual Studio, JetBrains, Xcode, Copilot CLI, GitHub.com 등에서 Pro·Pro+·Max 플랜에 순차 적용되며, Business·Enterprise 플랜은 기본값이 꺼져 있어 관리자가 별도로 활성화해야 한다.

**엔지니어 관점 포인트:**
중국계 랩의 오픈웨이트 모델이 처음으로 대형 상용 코딩 어시스턴트의 정규 라인업에 들어왔다는 점에서 폐쇄형 프론티어 모델과 오픈웨이트 모델 사이의 실무 격차가 빠르게 좁혀지고 있음을 보여준다. MIT 라이선스로 자체 호스팅이 가능하다는 점은 보안·규제 요건이 엄격한 기업 환경에서 실질적인 대안으로 검토될 만하다.

**관련 링크:** [GitHub Changelog - Kimi K2.7 Code in GitHub Copilot](https://github.blog/changelog/2026-07-01-kimi-k2-7-is-now-available-in-github-copilot/)

### 4. Microsoft Agent Framework, 1.11.0 업데이트로 MCP 툴 디스커버리·세션 관리 개선
**카테고리:** Agentic AI / Developer Tool

**주요 내용:**
- 지난 4월 Semantic Kernel과 AutoGen을 통합해 정식 출시된 Microsoft Agent Framework가 7월 10일자로 1.11.0 업데이트를 받았다. 에이전트 세션 관리 개선, 점진적(progressive) MCP 툴 디스커버리, 신규 스킬·호스팅 헬퍼, AG-UI 및 프로바이더 지원 강화가 핵심이다.
- 보안·안정성·샘플 커버리지도 전반적으로 개선됐으며, MCP 위에 스킬 개념을 얹는 설계 방향을 담은 아키텍처 결정 기록(ADR 0029)도 함께 추가됐다.

**엔지니어 관점 포인트:**
MCP 툴을 필요한 시점에만 불러오는 progressive discovery 방식은 대규모 툴 카탈로그를 다루는 에이전트가 안고 있던 컨텍스트 비용 문제를 실질적으로 완화하는 접근이다. 정식 출시 3개월 만에 이 정도 밀도로 업데이트가 나온다는 것은 실험적 오케스트레이션 프레임워크들이 빠르게 프로덕션 등급 SDK로 수렴하고 있으며, LangGraph·CrewAI 등 경쟁 프레임워크와의 표준화 경쟁도 본격화되고 있음을 시사한다.

**관련 링크:** [Microsoft Agent Framework Releases - GitHub](https://github.com/microsoft/agent-framework/releases)

### 5. MCP 2026-07-28 스펙, 완전 무상태(stateless) 구조로 전환하는 릴리스 후보 공개
**카테고리:** Agentic AI / Developer Tool

**주요 내용:**
- Model Context Protocol의 차기 스펙(2026-07-28)이 릴리스 후보 단계에 들어갔으며 최종 확정은 7월 28일이다. 핵심 변경은 프로토콜을 완전히 무상태로 전환하는 것으로, 기존의 initialize/initialized 핸드셰이크와 Mcp-Session-Id 헤더가 모두 제거된다.
- 리버스 DNS 식별자를 사용하는 Extensions 프레임워크, 서버가 클라이언트 내부에 인터랙티브 UI를 직접 렌더링하는 MCP Apps, OAuth 2.1·OpenID Connect 기반 인가 강화, 최소 12개월의 유예기간을 둔 공식 폐기 정책이 함께 도입됐다. Python, TypeScript, Go, C# SDK의 베타 버전도 이미 배포된 상태다.

**엔지니어 관점 포인트:**
세션 기반 상태 관리를 걷어내면 MCP 서버를 일반적인 라운드로빈 로드밸런서 뒤에 무상태로 배치할 수 있어 운영 복잡도가 크게 줄어든다. 다만 핸드셰이크와 세션 헤더 제거는 명백한 breaking change이므로, 현재 운영 중인 MCP 서버·클라이언트를 관리하는 팀은 7월 28일 최종 확정 전까지 마이그레이션 계획을 마련해 둘 필요가 있다.

**관련 링크:** [Model Context Protocol Blog - 2026-07-28 Release Candidate](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)

## 오늘의 트렌드 한눈에 보기
오늘 나온 소식들을 관통하는 흐름은 모델 자체의 절대 성능 경쟁보다 비용 대비 효율과 실제 운영 편의성 쪽으로 무게중심이 옮겨가고 있다는 점이다. GPT-5.6과 Grok 4.5는 거의 동시에 신모델을 내놓았지만 두 회사 모두 가격 경쟁력과 토큰 효율을 전면에 내세웠고, Kimi K2.7 Code가 GitHub Copilot 정규 라인업에 편입되면서 오픈웨이트 모델이 폐쇄형 프론티어 모델과 같은 상용 워크플로우 안에 자리 잡는 흐름도 다시 한번 확인됐다. 여기에 Microsoft Agent Framework의 업데이트와 MCP 2026-07-28 스펙의 무상태 전환은 에이전트를 실제 프로덕션에 배포하는 데 필요한 인프라와 프로토콜 계층이 빠르게 표준화되고 있음을 보여준다. 결국 오늘의 뉴스들은 어떤 모델이 가장 똑똑한가보다, 어떤 조합이 실제 운영에서 비용과 안정성을 함께 감당할 수 있는가로 질문의 중심이 옮겨가고 있음을 공통적으로 시사한다.
