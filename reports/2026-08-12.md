### 1. Nvidia, 첫 오픈소스 에이전트 실행 모델 Nemotron 3.5 Lightning 공개

**카테고리:** Open Source / Agentic AI

**주요 내용:**
- Nvidia가 8월 11일 오픈소스 모델 Nemotron 3.5 Lightning을 공개했다. 총 30B 규모의 Mixture-of-Experts(MoE) 구조에 활성 파라미터는 3B로, 상시 구동되는 에이전트의 실행 계층(execution layer)을 겨냥해 설계됐다.
- 단일 GPU가 장착된 PC에서 구동할 수 있을 만큼 경량이며, 기업이 별도 허가나 비용 없이 다운로드해 수정·사용할 수 있는 라이선스로 배포된다.
- 동급 모델 대비 출력 속도가 최대 4배 빠르고, 이를 통해 작업 완료 시간이 약 30% 단축된다고 회사 측은 밝혔다. 평가 방법론과 추론 소프트웨어, 데이터셋은 Nemotron Coalition 구성원들의 기여로 마련됐다.

**엔지니어 관점 포인트:**
이 모델의 초점은 '가장 똑똑한 모델'이 아니라 '에이전트 파이프라인에서 반복적으로 호출되는 실행 노드'에 맞춰져 있다. 대형 플래너 모델이 작업을 설계하고, 수많은 서브태스크를 저비용·고속 모델이 처리하는 계층 분리 구조가 실무 표준으로 굳어지는 흐름을 보여준다. 활성 파라미터 3B의 MoE라는 점은 로컬 또는 온프레미스에서 지연시간과 비용을 통제하면서 장시간 실행 에이전트를 돌리려는 팀에게 특히 매력적이다. 상용 API 호출 비용이 병목이던 워크플로우를 자체 인프라로 이전하는 선택지가 넓어졌다.

**관련 링크:** [NVIDIA Technical Blog](https://developer.nvidia.com/blog/nvidia-nemotron-3-5-lightning-delivers-fast-accurate-specialized-task-execution-for-long-running-agents/)

### 2. Model Context Protocol, 상태 비저장(stateless) 코어로 재설계된 2026-07-28 스펙 공개

**카테고리:** Developer Tool / Protocol

**주요 내용:**
- 에이전트와 업무 시스템을 연결하는 표준인 Model Context Protocol(MCP)이 2026-07-28 스펙을 내놓으며 프로토콜 코어를 상태 비저장 방식으로 전환했다. 프로토콜 수준의 세션과 Mcp-Session-Id 헤더를 제거해, 동일한 요청을 뒤단의 어느 서버 인스턴스든 처리할 수 있게 됐다.
- 이번 스펙에는 Multi Round-Trip Requests, 헤더 기반 라우팅, 캐시 가능한 list 결과, 인가(authorization) 강화, 그리고 공식 확장(extensions) 프레임워크가 포함됐다. MCP Apps, 보안 작업용 EMA 같은 사전 패키지 확장도 함께 제공된다.
- Tier 1 SDK 기준 월 다운로드가 5억 건에 육박하며, TypeScript와 Python SDK는 누적 다운로드 10억 건을 넘어섰다.

**엔지니어 관점 포인트:**
세션 상태를 프로토콜에서 걷어낸 것은 배포 아키텍처에 직접적인 영향을 준다. 기존에는 세션 고정(sticky session)이나 세션 스토어가 필요해 수평 확장과 장애 복구가 까다로웠지만, 상태 비저장 전환으로 일반적인 HTTP 로드밸런서 뒤에 MCP 서버를 그대로 늘려 세울 수 있게 됐다. 다만 세션 헤더 제거는 명백한 파괴적 변경(breaking change)이므로, 기존 MCP 서버·클라이언트를 운영 중이라면 마이그레이션 경로를 검토해야 한다. 확장 프레임워크의 등장은 MCP가 단순 도구 연결 규격을 넘어 에이전트 워크플로우 플랫폼으로 범위를 넓히고 있음을 시사한다.

**관련 링크:** [Model Context Protocol Blog](https://blog.modelcontextprotocol.io/posts/2026-07-28/)

### 3. Meta, 로컬 구동 오픈소스 모델 Muse Glimmer 공개하며 오픈소스 노선 재천명

**카테고리:** Open Source / LLM

**주요 내용:**
- Meta가 개인용 PC에서 구동 가능한 경량 오픈소스 모델 Muse Glimmer를 공개했다. 관대한(permissive) 오픈소스 라이선스로 배포되며, 더 강력한 상위 모델 Muse Spark 1.2에 대한 개발자 접근 경로도 함께 제공한다.
- Mark Zuckerberg는 핵심 구성요소를 누구나 열람·수정·확장할 수 있도록 공개하는 오픈소스 접근을 지지하는 이유를 담은 성명을 내놓으며 방향성을 분명히 했다.
- 이번 공개는 Nvidia의 Nemotron을 비롯해 최근 12일간 이어진 오픈소스 모델 출시 흐름의 연장선에 있다.

**엔지니어 관점 포인트:**
경량 로컬 모델과 상위 API 모델을 한 세트로 묶어 배포하는 방식은, 개발자가 프로토타이핑과 온디바이스 추론은 오픈 가중치로 처리하고 고난도 작업만 상위 모델로 넘기는 이원화 전략을 자연스럽게 유도한다. 프라이버시가 중요한 도메인이나 오프라인 환경에서 로컬 추론 선택지가 늘어난 점이 실질적이다. 대형 벤더들이 동시다발적으로 오픈 가중치 모델을 쏟아내면서, 폐쇄형 API에만 의존하지 않는 아키텍처 설계가 점점 현실적인 기본값이 되고 있다.

**관련 링크:** [PBS News](https://www.pbs.org/newshour/show/what-metas-new-open-source-ai-model-means-for-the-future-of-artificial-intelligence)

### 4. EU AI Act 제50조 투명성 의무 발효, AI 생성물 표시 의무화

**카테고리:** Policy / Compliance

**주요 내용:**
- 8월 2일부터 EU AI Act 제50조의 투명성 의무가 발효됐다. 사용자가 AI와 상호작용하고 있다는 사실을 고지하고, AI가 생성한 콘텐츠에는 기계 판독이 가능한(machine-readable) 표식을 적용하도록 요구한다.
- 이 규정은 AI 서비스를 EU 시장에 제공하는 기업 전반에 적용되며, 챗봇·생성형 콘텐츠·딥페이크 등 광범위한 사례를 포괄한다.

**엔지니어 관점 포인트:**
이 조항은 제품 UI와 데이터 파이프라인 양쪽에 실제 구현 과제를 안긴다. 생성물에 워터마크나 C2PA 계열 메타데이터 같은 기계 판독 표식을 삽입하는 기능, 그리고 사용자에게 AI 상호작용을 알리는 고지 UX를 제품에 내재화해야 한다. 특히 이미지·영상·음성 생성 기능을 다루는 팀이라면 콘텐츠 출처(provenance) 표준을 파이프라인 설계 단계부터 반영하는 편이 이후 규제 대응 비용을 크게 줄인다. 규제 준수가 사후 점검이 아니라 아키텍처 요구사항으로 이동하고 있다는 신호다.

**관련 링크:** [LLM Stats — AI News](https://llm-stats.com/ai-news)
