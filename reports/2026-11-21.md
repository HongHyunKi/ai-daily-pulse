### 2. Google Cloud Managed Service for Apache Spark 4.0, 에이전트형 운영 지원과 함께 GA
* **카테고리:** 데이터 플랫폼·에이전트 인프라
* **주요 내용:**
  - Google Cloud Managed Service for Apache Spark 4.0이 서버리스와 관리형 클러스터 배포를 대상으로 정식 출시됐다. 런타임은 Apache Spark 4.2, Java 25, Python 3.13(Pixi), Apache Iceberg 1.12를 표준화한다.
  - 실패한 작업의 로그·메트릭·쿼리 계획을 호출자의 기존 IAM 권한 안에서 분석해 원인과 수정 방향을 제안하는 AI 에이전트를 제공한다. Data Agent Kit은 MCP 서버·스킬·API 접근을 구성해 VS Code, Claude Code, Antigravity에서 Spark 파이프라인을 생성·튜닝·테스트할 수 있게 한다.
* **엔지니어 관점 포인트:**
  - GA 런타임 전환은 Spark·Java·Python·Iceberg 호환성을 먼저 검증하고, 에이전트 진단은 기존 IAM 경계와 데이터 접근 범위 안에서 별도 평가한다.
  - 진단 정확도, MTTR 감소, 비용 효과에 대한 공식 벤치마크는 노트에 없으므로 실제 실패 작업으로 측정한 뒤 운영 자동화 수준을 결정한다.
* **관련 링크:** [Google Cloud: Managed Service for Apache Spark 4.0](https://cloud.google.com/blog/products/data-analytics/whats-new-in-managed-service-for-apache-spark-4-0)

### 3. Google Cloud Unified Access Policies, 에이전트 ID를 일급 주체로 다루는 프리뷰
* **카테고리:** 클라우드 IAM·에이전트 보안
* **주요 내용:**
  - Unified Access Policies(UAP)는 허용·거부 규칙을 하나의 스키마로 묶고, 정책 정의와 리소스 적용을 분리한다. 특히 에이전트를 일반 서비스 계정이 아닌 일급 principal로 취급하는 방식이 핵심이다.
  - 프리뷰 기준 하나의 정책 바인딩은 조직·폴더·프로젝트 노드 최대 25개를 대상으로 하며, 리소스당 최대 5개 정책과 정책당 최대 100개 규칙을 지원한다. 콘솔·gcloud CLI·Terraform·Cloud IAM v3 REST API 경로가 제공된다.
* **엔지니어 관점 포인트:**
  - 아직 프리뷰이므로 테스트 프로젝트에서 에이전트 principal의 생성·전파·회수와 allow/deny 충돌을 검증하고, 프로덕션 권한 모델과 분리해 운용한다.
  - 지역 가용성, 프리뷰 SLA, 정식 출시 일정은 확인되지 않았으므로 해당 동작을 장기 계약이나 자동화의 유일한 기반으로 고정하지 않는다.
* **관련 링크:** [Google Cloud: Unified Access Policies](https://cloud.google.com/blog/products/identity-security/how-to-simplify-cloud-access-with-unified-access-policies)

* **카테고리:** 오픈소스·로컬 추론
* **주요 내용:**
  - Thinking Machines Lab의 Inkling 2 Mini는 모델 카드 기준 총 26.4B 파라미터, 3.4B 활성 파라미터의 루프형 멀티모달 MoE이며 최대 1M 토큰 컨텍스트와 이미지·텍스트 입력을 지원한다.
  - Apache 2.0 오픈웨이트로 공개됐고, 약 20GB 혼합 정밀도 체크포인트와 Transformers·SGLang·vLLM·llama.cpp·MLX·Ollama 등 실행 경로가 안내돼 있다. 모델 카드는 32GB 이상 메모리 또는 VRAM을 권장한다.
* **엔지니어 관점 포인트:**
  - 외부 API 의존도를 낮추려는 팀은 Apple silicon·소형 GPU·사내 서버에서 자체 평가할 수 있지만, 실제 메모리 여유·양자화·장문 컨텍스트 지연시간은 런타임별로 측정해야 한다.
  - Apache 2.0 조건과 모델 카드의 실행 제약을 확인한 뒤, 제품 품질·안전성·운영 비용을 상용 API와 같은 작업셋으로 비교한다.
* **관련 링크:** [Hugging Face: Inkling 2 Mini 소개](https://huggingface.co/blog/inkling2mini)

* **카테고리:** 오픈소스 추론 런타임·엣지 하드웨어
* **주요 내용:**

  - 릴리스 노트는 이 문제가 융합된 `ADD+RMS_NORM` 경로에서 잘못된 정규화와 장문 프롬프트 이후의 이상 토큰으로 이어질 수 있다고 설명한다. Adreno 850과 X2-90 테스트 보정 결과도 함께 제시됐다.
* **엔지니어 관점 포인트:**
  - Qualcomm Adreno Vulkan 백엔드에서 장문 프롬프트·반복 생성·정규화 결과를 회귀 테스트하고, 문제가 보이면 b12558 또는 이후 수정 버전을 우선 검토한다.
  - 프리릴리스이며 Qualcomm 경로에 초점이 맞춰진 수정이므로 CPU·CUDA 등 다른 백엔드의 일반적인 성능·호환성 개선으로 확대 해석하지 않는다.
