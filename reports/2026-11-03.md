### 1. GitHub, 보안 평가 결과에 저장소 보호 상태 표시
* **카테고리:** Developer Tool / Security
* **주요 내용:**
  - GitHub의 Code Security risk assessment와 Secret risk assessment가 각 발견 항목이 보호된 저장소에 있는지, 보호되지 않은 저장소에 있는지를 함께 보여준다.
  - 조직 관리자와 보안 관리자는 이 정보를 바탕으로 보안 적용 범위를 넓혀야 할 저장소를 식별할 수 있다. GitHub Enterprise Cloud와 GitHub Team에서 제공되며, GitHub Enterprise Server에서는 Secret risk assessment에 3.24 버전부터 제공될 예정이다.
* **엔지니어 관점 포인트:**
  - 새 스캐너가 추가된 것이 아니라, 기존 발견 결과와 보안 커버리지의 빈틈을 연결해 주는 운영 지표가 추가된 것이다.
  - AI 생성 코드와 의존성이 빠르게 늘어나는 조직은 취약점·시크릿 결과를 보는 데서 멈추지 말고, 보호되지 않은 저장소에 Code Security와 Secret Protection을 적용할 우선순위를 정하는 데 활용할 수 있다.
* **관련 링크:** [GitHub Changelog](https://github.blog/changelog/2026-11-02-security-risk-assessments-include-repository-protection-status/)

### 2. Google A2UI Python 코어 0.5.0 공개, v1.0 규칙 검증 강화
* **카테고리:** Agentic AI / Open Source
* **주요 내용:**
  - Google이 주도하는 A2UI의 `a2ui-core` 0.5.0이 11월 2일 공개됐다. 에이전트가 실행 가능한 코드를 보내는 대신 선언형 UI 설명을 보내고, 클라이언트가 네이티브 컴포넌트로 렌더링하는 프로토콜이다.
  - `allowed_callers`, 컴포넌트 참조와 위상 검증, v1.0 프로토콜 버전 값, `allowedParents`·`allowedChildren` 검증이 사양에 맞게 강화됐다. 일부는 기존에 허용되던 payload를 거부할 수 있는 호환성 변경이다.
* **엔지니어 관점 포인트:**
  - 생성형 UI를 제품에 넣을 때 모델이 임의 코드를 실행하지 못하게 하고, 클라이언트가 허용된 컴포넌트만 렌더링하는 설계가 구체적인 SDK 변경으로 굳어지고 있다.
  - 기존 A2UI Python 클라이언트는 `agentOnly` 함수 호출, 프로토콜 버전 문자열, 컴포넌트 트리 검증을 먼저 점검해야 한다. 단순 버전 업보다 fixture와 상호운용성 테스트를 함께 돌리는 편이 안전하다.
* **관련 링크:** [a2ui-core 0.5.0 Release](https://github.com/a2ui-project/a2ui/releases/tag/python%2Fa2ui-core%2Fv0.5.0)

### 3. Letta Code 0.34.38, 서브에이전트 진행 상황과 전체 JSONL 로그 추가
* **카테고리:** Agentic AI / Developer Tool
* **주요 내용:**
  - Letta Code가 0.34.38을 공개하며 서브에이전트의 진행 상황을 작업 출력 파일로 스트리밍하고, 원격 워커를 포함한 모든 서브에이전트 작업에 전체 JSONL 이벤트 로그를 남기도록 했다.
  - 에이전트 예제에서는 내부 이름과 ID를 공개 인터페이스처럼 다루지 않도록 문서도 정리했다.
* **엔지니어 관점 포인트:**
  - 멀티에이전트 시스템에서 결과만 받는 방식에서 벗어나, 중간 진행 상황과 이벤트를 관찰·재현·감사할 수 있는 실행 기록이 기본 구성요소가 되고 있다.
  - 사내 에이전트 런타임도 작업 상태를 구조화된 이벤트로 남기면 실패 원인 분석과 비용 추적이 쉬워진다. 다만 JSONL 로그에 프롬프트, 파일 내용, 토큰 같은 민감 정보가 들어갈 수 있으므로 보존 기간과 마스킹 정책을 함께 설계해야 한다.
* **관련 링크:** [Letta Code v0.34.38 Release](https://github.com/letta-ai/letta-code/releases)

### 4. ACP 에이전트 레지스트리, Kiro CLI와 최신 미리보기 버전 반영
* **카테고리:** Agentic AI / Open Source
* **주요 내용:**
  - Agent Client Protocol(ACP) 레지스트리가 11월 2일 여러 차례 갱신됐다. Kiro CLI를 ACP 에이전트로 추가했고, Codex ACP와 Claude ACP의 미리보기 버전을 각각 업데이트했다.
  - 같은 날 레지스트리에는 Autohand Code CLI 0.9.9의 네이티브 ACP 지원도 반영됐다. 기존 어댑터 대신 CLI 자체의 ACP 모드를 사용하도록 전환하는 내용이다.
* **엔지니어 관점 포인트:**
  - 에디터와 코딩 에이전트를 연결하는 공통 프로토콜이 개별 통합보다 중요한 배포 계층으로 자리 잡고 있다. 호스트가 에이전트를 직접 내장하기보다 레지스트리와 버전 메타데이터를 통해 선택지를 확장하는 흐름이다.
  - ACP 기반 통합을 운영한다면 레지스트리 자동 갱신만 믿기보다 실행 파일 버전, 체크섬, 인증 방식, 미리보기 채널 여부를 잠그는 검증 단계를 두는 것이 필요하다.
* **관련 링크:** [ACP Registry Releases](https://github.com/agentclientprotocol/registry/releases)

### 5. OpenHands SDK, 에이전트 서버의 설정 실패 시 fail-open 문제 공개
* **카테고리:** Agentic AI / Security
* **주요 내용:**
  - OpenHands Software Agent SDK에 손상되거나 복호화할 수 없는 `settings.json`을 읽지 못하면 기본 설정으로 대체하면서 확인 모드가 `NeverConfirm`이 될 수 있다는 고우선순위 이슈가 11월 2일 공개됐다.
  - 별도의 공개 수정 제안에서는 에이전트 서버가 명령과 출력을 평문으로 저장하지 않도록 bash 이벤트 파일을 Fernet으로 암호화하는 방안도 다뤄지고 있다. 이 내용은 확인된 보안 개선 작업이며, 이번 시점에 공식 릴리스 완료로 단정할 수는 없다.
* **엔지니어 관점 포인트:**
  - 에이전트 보안은 프롬프트 인젝션 방어만의 문제가 아니다. 설정 파일의 파싱 실패를 안전한 중단으로 처리하지 않고 권한이 넓은 기본값으로 폴백하면, 정상적인 운영 오류가 승인 없는 도구 실행으로 이어질 수 있다.
  - 에이전트 런타임은 설정 불명확 상태를 별도 상태로 취급하고 fail-closed 해야 한다. 명령·출력·토큰이 포함될 수 있는 실행 로그도 저장 시 암호화하고, 키가 없을 때의 동작을 테스트에 포함해야 한다.
* **관련 링크:** [OpenHands 보안 이슈 #6370](https://github.com/OpenHands/software-agent-sdk/issues/6370) · [bash 이벤트 암호화 수정 제안](https://github.com/OpenHands/software-agent-sdk/pull/6343)

- 생성형 UI는 선언형 프로토콜과 엄격한 스키마 검증을 통해 실행 코드와 렌더링 데이터를 분리하는 방향으로 진화하고 있다.
- 멀티에이전트 런타임은 진행 상태와 구조화된 이벤트 로그를 기본 기능으로 끌어올리고 있으며, 운영팀은 로그의 민감 정보 처리까지 함께 책임져야 한다.
- ACP처럼 에디터와 에이전트를 연결하는 공통 프로토콜의 레지스트리가 커지면서, 통합의 핵심은 모델 선택보다 버전·권한·배포 검증으로 이동하고 있다.
- 에이전트 시스템의 안전한 기본값은 선택 기능이 아니다. 설정 오류와 저장 실패를 허용 확대가 아닌 실행 중단으로 처리하는 설계가 필요하다.
