## 오늘의 핵심 AI 뉴스 요약

### 1. GitHub, Copilot에 검증된 MCP 커넥터 8종 추가

* **카테고리:** Developer Tool / Agentic AI / MCP
* **주요 내용:** GitHub가 Box, Buildkite, Calendly, ClickUp, Mixpanel, Supabase, Webflow, Wix를 GitHub-verified MCP 커넥터로 추가했다. 커넥터는 Copilot 앱, Copilot CLI, VS Code, github.com에서 사용할 수 있는 공개 프리뷰다. 예를 들어 Copilot이 Buildkite 빌드 실패 원인을 확인하고 코드 수정까지 이어가거나, Supabase 스키마를 조회한 뒤 마이그레이션을 작성하는 흐름을 구성할 수 있다. Business·Enterprise에서는 `Editor preview features` 정책이 필요하고, 항목별 MCP 허용 목록을 쓰는 조직은 새 커넥터를 별도로 허용해야 한다.
* **엔지니어 관점 포인트:** 빌드·데이터베이스·분석·업무 도구의 컨텍스트를 프롬프트로 복사하지 않고 코딩 에이전트 루프에 연결할 수 있다. 다만 공개 프리뷰인 만큼 커넥터별 권한, 관리자 승인, 허용 목록을 에이전트의 운영 공격면으로 다뤄야 하며, 요금·호출 제한·데이터 보존 정책은 운영 의존성으로 채택하기 전에 확인해야 한다.
* **관련 링크:** [GitHub Changelog — Connect Supabase, Box, Calendly, and more to Copilot](https://github.blog/changelog/2026-11-18-connect-supabase-box-calendly-and-more-to-copilot/)

### 2. Google Cloud, Cloud SQL 변경을 복제본에서 검증하는 에이전틱 평가 공개

* **카테고리:** Cloud Database / Agentic AI / Performance Engineering
* **주요 내용:** Google Cloud가 Database Center에서 Cloud SQL for PostgreSQL 인스턴스의 권장 변경을 복제본으로 시험하는 에이전틱 평가 기능을 프리뷰로 공개했다. 지원되는 권장 사항에서 `Assess impact`를 실행하면 테스트 계획을 만들고, 기본 합성 워크로드를 실행한 뒤 권장 변경을 복제본에 적용하고, 다시 벤치마크해 트랜잭션 처리량·평균 지연시간·CPU·메모리 사용량 등의 전후 결과를 비교한다. 초기 범위는 머신 업그레이드, Cloud SQL Enterprise에서 Enterprise Plus로의 업그레이드, 데이터 캐시 활성화이며 Cloud SQL for PostgreSQL에 한정된다.
* **엔지니어 관점 포인트:** 운영 DB를 바로 변경하지 않고 격리된 환경에서 리사이징·에디션·캐시 변경의 방향성을 확인할 수 있어 DBA/SRE 검증 작업을 반복 가능한 흐름으로 바꾼다. 복제본과 벤치마크 리소스는 과금 대상이고, 취소·실패한 세션은 수동 정리가 필요할 수 있으며 평가 계획과 결과는 48시간 보관된다. 합성 `pgbench` 결과는 실제 업무 부하의 대체물이 아니므로 최종 승인 전에는 서비스 트래픽으로 별도 검증해야 한다.
* **관련 링크:** [Google Cloud Blog — Testing changes, fast: Introducing agentic assessments in Database Center](https://cloud.google.com/blog/products/databases/database-center-assessments-for-cloud-sql-for-postgresql)

### 3. AWorld v0.3.0, A2A·MCP와 워크스페이스를 에이전트 런타임에 결합

* **카테고리:** Open Source / Agent Framework / MCP
* **주요 내용:** AWorld가 v0.3.0을 릴리스하며 실험적 에이전트 서버에 A2A와 MCP 지원을 추가했다. 릴리스에는 Skills, 컨텍스트 구현 개선, 스트리밍 응답 API, 워크스페이스 파일 업로드·다운로드, 샌드박스·MCP 개선, trajectory·trace 개선이 함께 포함됐다.
* **엔지니어 관점 포인트:** 멀티에이전트 간 통신과 도구 연결뿐 아니라 재사용 가능한 스킬, 파일 기반 작업 공간, 스트리밍, 추적까지 한 프레임워크 안에서 평가할 수 있게 됐다. 다만 A2A/MCP 서버가 실험적이라고 명시돼 있고 독립적인 호환성·운영 안정성 자료는 확인되지 않으므로, 기존 오케스트레이션을 즉시 교체하기보다 격리된 워크플로에서 프로토콜 호환성과 장애 복구를 검증하는 편이 안전하다.
* **관련 링크:** [AWorld v0.3.0 Release](https://github.com/inclusionAI/AWorld/releases/tag/v0.3.0)

### 4. openai-python v3.55.0, Live MCP 서버 설정을 SDK API에 추가

* **카테고리:** SDK / Developer Tool / MCP
* **주요 내용:** 공식 `openai-python` v3.55.0이 Live MCP server configuration을 API 기능으로 추가했다. 릴리스에는 Managed Agents 세션 예산 제어와 이벤트를 공개 API 표면에서 숨기는 변경도 포함됐다. 이번 릴리스 노트는 Live MCP 설정 기능의 추가 사실은 밝히지만, 구체적인 Python 호출 예제나 호환성 매트릭스까지 제공하지는 않는다.
* **엔지니어 관점 포인트:** Python 애플리케이션에서 MCP 설정을 공식 SDK 경로로 추적할 수 있는 기반이 생겼으므로, 도입 전 생성 타입·요청 구성·통합 테스트의 변화를 확인할 가치가 있다. 실제 메서드와 매개변수 이름은 릴리스 노트만으로 확정할 수 없으므로, 문서와 설치한 패키지의 타입을 확인하기 전까지 호출 형태를 코드에 추정해 넣어서는 안 된다.
* **관련 링크:** [openai-python v3.55.0 Release](https://github.com/openai/openai-python/releases/tag/v3.55.0)

### 5. vLLM, `/v1/systemone`의 chat-template 신뢰 경계 우회 취약점 수정

* **카테고리:** AI Infrastructure / Security
* **주요 내용:** vLLM 보안 권고 `GHSA-xgh8-qwjh-q853`에 따르면 vLLM **0.32.0rc0부터 0.33.0까지**의 `/v1/systemone` 경로가 요청의 `chat_template_kwargs`를 렌더러에 전달하면서 `validate_chat_template()`를 호출하지 않아, 엔드포인트에 접근할 수 있는 호출자가 운영자가 고정한 시스템 직렬화를 바꾸고 특수 토큰이나 턴 경계를 주입할 수 있었다. 권고의 심각도는 Moderate(CVSS 6.5)이며 수정 버전은 **0.34.0**이다.
* **엔지니어 관점 포인트:** 영향 범위에 해당하는 배포는 **vLLM 0.34.0으로 업그레이드**하고, `/v1/systemone`이 낮은 권한의 호출자에게 노출돼 있었는지 점검해야 한다. 취약 버전에서는 `--trust-request-chat-template` 옵션만으로 해당 경로를 보호할 수 없으므로 네트워크 접근 제어와 인증 정책도 함께 확인해야 한다. 권고가 설명하는 핵심은 Jinja 샌드박스 탈출이나 자원 고갈이 아니라 요청 템플릿 신뢰 경계와 보호 기제의 우회다.
* **관련 링크:** [vLLM Security Advisory — GHSA-xgh8-qwjh-q853](https://github.com/vllm-project/vllm/security/advisories/GHSA-xgh8-qwjh-q853)

## 오늘의 트렌드 한눈에 보기

- 에이전트 개발의 중심이 모델 호출에서 **외부 시스템 연결·파일 작업·프로토콜 상호운용성·추적**을 포함한 실행 인프라로 이동하고 있다. GitHub의 검증된 MCP 커넥터와 AWorld의 A2A/MCP·워크스페이스 확장은 이 흐름을 각각 SaaS 통합과 오픈소스 런타임에서 보여준다.
- 에이전틱 기능이 운영 변경의 사전 검증으로 확장되고 있다. Database Center는 프로덕션 DB를 직접 바꾸지 않고 복제본에서 합성 부하로 변경 효과를 비교하게 해, 자동화의 경계를 ‘변경 실행’보다 ‘변경 판단 지원’에 둔다.
- MCP가 제품 기능을 넘어 SDK와 조직 정책의 관리 대상이 되고 있다. 따라서 도입 시 연결 가능한 서버 목록, 사용자·서비스 계정 권한, 감사 로그, 프리뷰 기능의 변경 가능성을 함께 관리해야 한다.
- AI 인프라의 신뢰 경계는 일반 웹 서비스와 다르지 않다. vLLM 사례처럼 요청 입력이 템플릿·도구·모델 동작을 바꿀 수 있으므로, 버전 패치와 엔드포인트 노출 점검을 모델 성능 검증만큼 정기화해야 한다.
