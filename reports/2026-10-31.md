## 오늘의 핵심 AI 뉴스 요약

### 1. Android Studio Rabbit 2, 40개 이상 코딩 에이전트 지원
* **카테고리:** Developer Tool / Agentic AI
* **주요 내용:**
  - Google이 Android Studio Rabbit 2를 안정 버전으로 출시하고, ACP(Agent Client Protocol)를 준수하는 40개 이상의 코딩 에이전트를 IDE 안에서 선택할 수 있게 했습니다.
  - Claude Agent, OpenAI Codex, Google Antigravity 등을 Android Emulator, 빌드 시스템, Logcat, Android skills와 함께 사용할 수 있습니다.
  - Android CLI에는 실제 기기 스트리밍, Compose 미리보기, Perfetto 기반 프로파일링, 앱 품질 분석 기능이 추가됐고, LeakCanary·AI Change Review도 통합됐습니다.
* **엔지니어 관점 포인트:**
  - Android 개발의 경쟁 축이 특정 모델의 내장 여부에서 에이전트 교체 가능성과 개발 도구 접근성으로 이동하고 있습니다.
  - 에이전트가 실제 기기·프리뷰·성능 추적 결과까지 다루게 되면서, 생성 코드보다 검증 루프를 자동화하는 IDE 기능의 가치가 커집니다.
* **관련 링크:** [Android Studio Rabbit 2 에이전트 통합 발표](https://developer.android.google.cn/blog/posts/ai-agents-android-studio-integration?hl=en)

### 2. GitHub Copilot, 어디서나 이어지는 cloud 세션 공개
* **카테고리:** Developer Tool / Agentic AI
* **주요 내용:**
  - GitHub가 github.com, 모바일, Copilot CLI·앱, VS Code, Slack, Microsoft Teams 사이에서 동일한 Copilot cloud 세션을 이어갈 수 있는 연결형 경험을 공개했습니다.
  - 세션은 기본적으로 GitHub 관리형 보안 cloud sandbox에서 실행되며, 스냅샷을 저장해 중단 후 재개할 수 있습니다.
  - GitHub Actions 사용량과 cloud sandbox·대형 hosted runner가 하나의 금액 기반 compute entitlement를 공유하며, cloud sandbox 사용량 과금은 2026년 11월부터 시작됩니다.
* **엔지니어 관점 포인트:**
  - 코딩 에이전트가 IDE 보조 기능에서 모바일·협업 도구·CI를 잇는 비동기 실행 환경으로 확장되고 있습니다.
  - 팀은 세션 재개 지점, 저장되는 컨텍스트, MCP·connector 권한, 조직별 SSO 범위를 운영 정책과 함께 설계해야 합니다.
* **관련 링크:** [GitHub Copilot 연결형 cloud 경험 발표](https://github.blog/changelog/2026-10-28-work-from-anywhere-with-a-new-connected-copilot-cloud-experience/)

### 3. Microsoft, GitHub Copilot harness를 Foundry에 제공
* **카테고리:** Agentic AI / Platform
* **주요 내용:**
  - Microsoft가 GitHub Copilot 제품군에서 사용해 온 멀티모델 harness를 Microsoft Foundry를 통해 개발자와 기업에 제공한다고 발표했습니다.
  - harness는 모델 자체가 아니라 지시, 컨텍스트, 실행 환경, 권한 제어, MCP·agent skills·plugins를 묶는 오케스트레이션 계층입니다.
  - Microsoft는 20개 이상의 frontier 모델과 BYOK를 지원하고, 작업에 맞는 모델을 선택·조합하는 라우팅을 목표로 제시했습니다.
* **엔지니어 관점 포인트:**
  - 모델 교체 비용을 낮추려면 애플리케이션 코드보다 harness의 상태 관리, 도구 권한, 평가·관측 계층을 표준화하는 편이 중요해집니다.
  - 다중 모델 라우팅은 품질뿐 아니라 토큰 비용, 지연 시간, 데이터 경계까지 함께 평가해야 하므로 단일 모델 벤치마크만으로는 부족합니다.
* **관련 링크:** [Microsoft Copilot harness 발표](https://blogs.microsoft.com/blog/2026/10/28/introducing-the-microsoft-copilot-harness-unlocking-the-potential-of-truly-multi-model-agentic-work/)

### 4. Mistral Large 4, 1조 파라미터 오픈 웨이트 공개
* **카테고리:** LLM / Open Weight / Agentic AI
* **주요 내용:**
  - Mistral이 멀티모달 MoE 모델 Mistral Large 4(Le Chonk)의 가중치를 공개했습니다. 총 파라미터는 약 1조 개이며, 약 490억 개의 활성 파라미터를 사용하는 모델 계열입니다.
  - Mistral은 추가 강화학습 후 코딩·방어적 사이버보안 성능과 추론 효율이 개선됐다고 설명했으며, 세 가지 reasoning 모드와 vLLM·SGLang 기반 자체 배포 경로를 제공합니다.
  - Mistral Ecosystem Open-Weight 라이선스는 사용·수정·상용화를 허용하지만, Model-as-a-Service로 제공하려면 별도 상업 라이선스가 필요합니다.
* **엔지니어 관점 포인트:**
  - 코딩 에이전트와 보안 분석을 자체 인프라에서 운영하려는 팀에게 성능·데이터 주권·비용을 함께 검토할 수 있는 선택지가 늘었습니다.
  - 1조 파라미터급 모델은 하드웨어와 운영 비용이 크므로, 실제 도입 전 양자화·배치 크기·긴 컨텍스트 비용을 자사 워크로드로 측정해야 합니다.
* **관련 링크:** [Mistral Large 4 오픈 웨이트 공개](https://mistral.ai/news/mistral-large-4-oss/)

### 5. OpenAI, 여러 AI 제공자가 함께 쓰는 `robots.txt` 선호 신호 지원
* **카테고리:** AI Policy / Web Infrastructure
* **주요 내용:**
  - OpenAI가 웹사이트 운영자가 여러 AI 제공자에게 콘텐츠의 기초 생성형 AI 학습 사용 선호를 한 번에 전달할 수 있는 공통 신호를 `robots.txt`에서 존중하겠다고 발표했습니다.
  - 지금까지 제공자별 크롤러 규칙을 따로 관리하던 부담을 줄이는 것이 목표이며, IETF AI Preferences working group의 논의를 기반으로 합니다.
  - 구현은 앞으로 수개월 내 진행될 예정이고, 기존 OpenAI crawler controls를 대체하지는 않습니다.
* **엔지니어 관점 포인트:**
  - 이는 즉시 적용되는 표준 확정이 아니라, 웹 크롤링과 AI 학습 선호를 다루는 상호운용성 논의가 제품 정책으로 이동한 신호입니다.
  - 콘텐츠 제공자는 공통 신호의 실제 문법·지원 범위·감사 가능성을 확인한 뒤 기존 크롤러 허용/차단 정책과 함께 테스트해야 합니다.
* **관련 링크:** [OpenAI의 공통 AI 학습 선호 신호 지원 발표](https://openai.com/index/helping-websites-express-ai-training-preferences/)
