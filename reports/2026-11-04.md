## 오늘의 핵심 AI 뉴스 요약

### 1. GitHub Copilot, JetBrains Air에서 ACP 기반 코딩 작업 지원
* **카테고리:** Developer Tool / Agentic AI
* **주요 내용:**
  - GitHub Copilot을 JetBrains Air의 에이전트 선택기에서 사용할 수 있게 됐다. Agent Client Protocol(ACP)을 통해 JetBrains IDE 안의 로컬 작업과 클라우드 작업을 모두 지원한다.
  - 여러 에이전트 세션을 병렬로 추적하고 프로젝트 컨텍스트와 IDE 도구를 활용하면서 결과를 같은 화면에서 검토할 수 있다.
  - Air Teams의 클라우드 작업은 새 가상 머신의 Docker 컨테이너에서 실행되며, 프록시를 거치고 작업 사이에 상태가 유지되지 않는다. 사용량은 JetBrains AI 크레딧이 아니라 GitHub Copilot 플랜에 반영된다.
* **엔지니어 관점 포인트:**
  - 코딩 에이전트가 특정 IDE 플러그인의 부가 기능을 넘어, ACP를 통한 교체 가능한 실행 백엔드로 들어오고 있다. IDE·에이전트 조합을 설계할 때 프로토콜 호환성이 중요한 선택 기준이 된다.
  - 클라우드 작업은 격리 환경에서 실행되지만, Air 관리자에게 Copilot별 지출 한도나 사용량 분석이 제공되지는 않는다. 조직 도입 전에는 저장소 권한, 비용 관측, 네트워크 프록시 정책을 별도로 점검해야 한다.
* **관련 링크:** [GitHub Changelog](https://github.blog/changelog/2026-11-03-github-copilot-is-now-available-in-jetbrains-air/)

### 2. Dependabot, Agent Package Manager 의존성 업데이트 지원
* **카테고리:** Developer Tool / Open Source / Security
* **주요 내용:**
  - GitHub Dependabot이 Agent Package Manager(APM)의 `apm.yml`에 선언된 Git 의존성 버전을 자동으로 업데이트하고, `apm.lock.yaml`이 있으면 함께 재생성한다.
  - GitHub.com의 모든 플랜에서 일반 제공되며 GitHub Enterprise Server 3.24에도 포함될 예정이다.
  - 이번 기능은 버전 업데이트용이며 보안 업데이트까지 처리하는 기능은 아니다. `.github/dependabot.yml`에 `apm` 항목과 대상 디렉터리, 실행 주기를 지정해 사용한다.
* **엔지니어 관점 포인트:**
  - 프롬프트·에이전트 스킬·지침을 저장소 의존성으로 관리하는 팀은 이제 일반 코드와 비슷한 업데이트 PR 흐름을 적용할 수 있다. 에이전트 동작의 재현성과 변경 이력 추적에 도움이 된다.
  - 자동 업데이트가 곧 안전한 업데이트를 뜻하지는 않는다. 스킬과 지침은 실행 권한과 동작 범위를 바꿀 수 있으므로, PR 검토와 lockfile 고정, 실행 회귀 테스트를 공급망 관리의 일부로 두어야 한다.
* **관련 링크:** [GitHub Changelog](https://github.blog/changelog/2026-11-03-dependabot-version-updates-support-agent-package-manager/)

### 3. CodeQL 2.27.3, LLM 생성 데이터를 위한 옵트인 위협 모델 추가
* **카테고리:** Developer Tool / Security
* **주요 내용:**
  - CodeQL 2.27.3이 Python 3.15 문법과 C23 비트 정밀 정수, JSON 데이터 확장을 지원한다.
  - LLM이 생성하거나 변환한 데이터를 별도의 오염원으로 모델링할 수 있는 `ai` 위협 모델이 추가됐다. 기본 소스 모델은 포함되지 않으므로 사용자가 데이터 확장으로 소스를 정의해야 한다.
  - Python의 `frozendict`·`sentinel` 모델링과 여러 언어의 데이터 흐름 정확도 개선도 포함됐다. GitHub Actions의 CFG 내부 변경으로 일부 사용자 정의 쿼리는 수정이 필요할 수 있다.
* **엔지니어 관점 포인트:**
  - AI 생성 코드나 모델 출력이 이후 SQL, URL, 명령 실행 경로로 흘러가는 문제를 기존 정적 분석 흐름 안에서 명시적으로 표현할 수 있는 기반이 생겼다.
  - 기능이 옵트인이고 소스 정의가 비어 있으면 원하는 결과가 나오지 않는다. 먼저 조직의 모델 호출·생성 파일·자동 수정 봇을 신뢰 경계로 목록화한 뒤, 작은 데이터 확장과 회귀 쿼리로 적용 범위를 검증하는 편이 안전하다.
* **관련 링크:** [GitHub Changelog](https://github.blog/changelog/2026-11-03-codeql-2-27-3-adds-python-3-15-features-and-json-data-extensions/)

### 4. Hugging Face, 모델 회귀를 고정하는 Model Integration Contracts 제안
* **카테고리:** Open Source / LLM Infrastructure
* **주요 내용:**
  - Hugging Face가 `transformers-mic`을 통해 모델 통합 테스트를 fixture, 실행 가능한 사용 예제, 사람이 검토한 baseline 출력으로 묶는 Model Integration Contract(MIC)를 제안했다.
  - 축소·고정한 모델 fixture를 사용해 실제 checkpoint 로딩 경로와 생성·학습·optimizer step을 CI에서 재검증한다. 모델 아키텍처와 사용 경로를 계약 단위로 다루므로 호환 checkpoint가 fixture를 공유할 수 있다.
  - CLI `tmic`은 LLM으로 계약 초안을 만들 수 있지만, 기대값 변경은 사람의 검토가 필요하다. 공개된 실험에서는 overfit fixture가 주입된 24개 결함을 모두 잡았고 random fixture는 24개 중 18개를 잡았다.
* **엔지니어 관점 포인트:**
  - 모델 라이브러리의 대규모 통합 테스트를 매번 전체 checkpoint와 GPU로 돌리는 대신, 작고 재현 가능한 계약으로 PR 검증 비용을 낮추려는 접근이다.
  - 생성형 테스트 코드와 baseline을 에이전트가 만들더라도 승인 주체는 사람이어야 한다. fixture 버전, 패키지 버전, baseline 변경 이력을 함께 고정하지 않으면 회귀 테스트가 조용히 무력화될 수 있다.
* **관련 링크:** [Hugging Face Blog](https://huggingface.co/blog/transformers-mic)

### 5. CWE-bench v2, 보안 취약점 수정 에이전트용 공개 평가셋 확대
* **카테고리:** Agentic AI / Security / Open Source
* **주요 내용:**
  - CWE-bench v2가 실제 오픈소스 저장소에서 취약점을 찾고 기존 기능을 깨뜨리지 않고 수정하는 100개 공개 작업을 제공한다. 각 작업은 Docker 환경, 짧은 지시문, 결정론적 검증기로 구성된다.
  - 점수는 프로그램으로 계산되어 재현할 수 있고, 데이터셋·grader·harness가 공개됐다. Harbor를 사용하면 Hugging Face 저장소에서 작업을 내려받아 에이전트와 모델을 바로 평가할 수 있다.
  - 공개 리더보드의 11개 모델 비교에서는 Gemini 4 Argon이 pass@1 67.8%, pass@4 81.0%로 앞섰지만, 선두 모델도 모든 시도에서 19%의 작업을 해결하지 못했다. 이 수치는 해당 평가셋의 공개 결과이며 일반적인 보안 능력의 증명은 아니다.
* **엔지니어 관점 포인트:**
  - 보안 코딩 에이전트를 데모가 아닌 고정된 저장소·검증기·비용 조건으로 비교할 수 있는 기준이 늘었다. 자체 에이전트를 도입할 때도 성공률만이 아니라 회귀 테스트 통과와 rollout 비용을 함께 기록할 수 있다.
  - 데이터셋이 공개된 만큼 학습·프롬프트 오염과 memorized solution 문제를 별도로 관리해야 한다. 공개셋 점수는 개발용 신호로 사용하고, 운영 판단에는 held-out 평가와 실제 내부 코드의 재현 가능한 검증을 추가해야 한다.
* **관련 링크:** [Hugging Face Blog](https://huggingface.co/blog/cwe-bench)

## 오늘의 트렌드 한눈에 보기
- 에이전트는 IDE 안에서 병렬 작업을 수행하는 실행 계층으로 들어오고 있으며, ACP 같은 공통 프로토콜이 통합 비용을 낮추고 있다.
- 에이전트 스킬과 지침도 의존성으로 취급되기 시작하면서 lockfile, 업데이트 PR, 리뷰 같은 공급망 관리 방식이 중요해졌다.
- 모델 출력과 AI 생성 코드의 보안 위험을 정적 분석과 벤치마크에 직접 넣으려는 흐름이 강해지고 있다.
- 모델·에이전트 품질 검증은 전체 시스템을 한 번 돌려보는 방식에서, 고정 fixture·결정론적 verifier·비용 지표를 결합한 회귀 평가로 이동하고 있다.
