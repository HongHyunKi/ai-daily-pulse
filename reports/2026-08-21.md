### 1. Nvidia, 단일 GPU에서 도는 오픈소스 에이전트 모델 Nemotron 3.5 Lightning 공개
**카테고리:** Open Source / Agentic AI

**주요 내용:**
- Nvidia가 8월 11일 300억 파라미터 규모의 오픈소스 모델 Nemotron 3.5 Lightning을 공개했다. 토큰당 활성 파라미터는 30억으로, Mamba-2와 MoE, 어텐션을 결합한 하이브리드 아키텍처에 1M 토큰 컨텍스트 윈도우를 갖췄다.
- MoE 구조로 토큰당 30억 파라미터만 활성화되기 때문에 RTX PC나 DGX Spark 같은 소비자용 단일 GPU에서도 구동된다. 더 큰 Nemotron 3 Ultra에서 증류한 모델로, 대량 에이전트 워크로드를 겨냥해 설계됐다.
- Nvidia는 동급 오픈 모델 대비 출력 속도가 최대 4배 빠르고 에이전트 작업 완료 시간이 약 30% 단축된다고 밝혔다. 가중치와 학습 데이터, 레시피가 OpenMDW-1.1 라이선스로 함께 공개돼 상업적 사용에 별도 허가나 비용이 필요 없다.
- 요청을 작업별로 가장 효율적인 모델에 라우팅하는 오픈소스 라이브러리 NeMo Switchyard도 동반 공개됐다.

**엔지니어 관점 포인트:**
장시간 실행되는 에이전트 파이프라인에서 가장 큰 비용은 결국 추론 단가와 처리량이다. 30B 규모이면서도 활성 파라미터를 3B로 눌러 단일 GPU에서 돌릴 수 있다는 점은, 프론티어 API에 의존하던 반복적·고빈도 에이전트 작업을 온프레미스나 로컬 인프라로 내재화할 수 있는 현실적인 선택지를 제공한다. 특히 OpenMDW-1.1이라는 관대한 라이선스로 가중치와 학습 레시피까지 공개된 점은 파인튜닝과 도메인 특화가 필요한 팀에게 진입 장벽을 크게 낮춘다. NeMo Switchyard와 함께 쓰면 단일 거대 모델 대신 작업별로 경량 모델을 선택 호출하는 라우팅 아키텍처를 구성할 수 있어, 비용 최적화 관점에서 검토할 가치가 크다.

**관련 링크:** [MarkTechPost](https://www.marktechpost.com/2026/08/11/nvidia-ai-releases-nemotron-3-5-lightning-and-nemo-switchyard/), [NVIDIA Developer Blog](https://developer.nvidia.com/blog/nvidia-nemotron-3-5-lightning-delivers-fast-accurate-specialized-task-execution-for-long-running-agents/)

### 2. Z.ai, 사전학습 없이 코딩·장기 태스크를 끌어올린 GLM-5.3 출시
**카테고리:** LLM / Coding

**주요 내용:**
- Z.ai가 8월 14일 플래그십 코딩·에이전트 모델 GLM-5.3을 공개했다. GLM-5.2와 동일한 743B 파라미터 베이스 위에서 후처리 학습만 확장했으며, 새로운 사전학습 없이 성능 향상을 이뤄냈다고 밝혔다.
- 코딩·에이전트 벤치마크에서 큰 폭의 개선을 보였다. Terminal-Bench 3.0이 GLM-5.2의 4.6에서 28.3으로, DeepSWE v1.1은 46.2에서 66.9로 올랐고, 내부 코딩 에이전트 평가에서는 GLM-5.2 대비 약 50% 향상됐다.
- 사이버보안 벤치마크 CyberGym에서 84.5%를 기록해 Anthropic Mythos 5(83.8%)와 OpenAI GPT-5.6 Sol(83.6%)을 근소하게 앞섰다.
- 우선 GLM Coding Plan과 ZCode를 통해 제공되며, 독립 API는 준비 중, 오픈 가중치는 약 2주 후 공개가 예고됐다.

**엔지니어 관점 포인트:**
GLM-5.3에서 주목할 지점은 성능 향상의 출처가 사전학습이 아니라 후처리 학습이라는 사실이다. 이는 동일 베이스 모델을 유지하면서 포스트트레이닝만으로도 코딩 에이전트의 장기 태스크 수행력을 끌어올릴 수 있음을 보여주는 사례로, 막대한 사전학습 비용 없이 반복 개선이 가능하다는 신호다. Terminal-Bench가 4.6에서 28.3으로 여섯 배 가까이 뛴 것은 터미널 기반 자동화나 CI 파이프라인 안에서 도는 코딩 에이전트에 실질적 의미가 있다. 오픈 가중치 공개가 예고된 만큼, 자체 인프라에서 코딩 어시스턴트를 운영하려는 팀은 라이선스 조건과 함께 도입 여부를 저울질해 볼 만하다.

**관련 링크:** [SiliconANGLE](https://siliconangle.com/2026/08/14/z-ai-debuts-glm-5-3-long-horizon-coding-cybersecurity-upgrades/), [MarkTechPost](https://www.marktechpost.com/2026/08/14/z-ai-ships-glm-5-3-without-retraining-the-base-model-better-at-complex-coding-and-long-horizon-tasks/)

### 3. Cloudflare, Agents Week 2026에서 에이전트 전용 인프라 대거 공개
**카테고리:** Developer Tool / Agentic AI

**주요 내용:**
- Cloudflare가 8월 초 Agents Week 2026을 열고 자율 소프트웨어를 위한 컴퓨팅, 스토리지, 보안, 개발 도구를 아우르는 생태계를 발표했다.
- 컴퓨팅·스토리지 영역에서는 셸과 파일시스템, 백그라운드 프로세스를 갖춘 격리 환경 Sandboxes와, 에이전트·개발자·자동화가 코드를 저장할 Git 호환 버전 관리 스토리지 Artifacts가 공개됐다. 워크플로 엔진은 동시 인스턴스 4,500개에서 5만 개로, 생성 속도 초당 100개에서 300개로 확장됐다.
- 보안 측면에서는 RFC 9728을 채택한 Managed OAuth for Cloudflare Access를 통해 에이전트가 서비스 계정 없이 내부 애플리케이션에 안전하게 접근하도록 지원한다.
- 웹사이트가 에이전트 상호작용을 얼마나 잘 지원하는지 점수를 매기는 무료 도구 isitagentready.com도 함께 선보였다.

**엔지니어 관점 포인트:**
Cloudflare의 이번 발표는 에이전트를 하나의 애플리케이션 클래스로 취급하는 인프라 흐름을 선명하게 보여준다. 격리된 Sandboxes와 Git 호환 Artifacts는 그동안 각 팀이 직접 구축하던 에이전트 실행 환경과 상태 저장 계층을 매니지드 서비스로 대체할 수 있게 한다. 특히 RFC 9728 기반 Managed OAuth는 에이전트가 내부 시스템에 접근할 때 관행처럼 쓰이던 취약한 서비스 계정 문제를 표준 인증으로 풀어낸다는 점에서 보안 설계상 의미가 크다. 에이전트 워크로드를 프로덕션에 올리려는 팀이라면 실행·저장·인증 계층을 자체 구축할지 이런 매니지드 프리미티브 위에 얹을지 아키텍처 결정을 앞당겨 검토할 필요가 있다.

**관련 링크:** [Cloudflare Blog](https://blog.cloudflare.com/agents-week-in-review/), [VKTR](https://www.vktr.com/ai-news/cloudflare-agents-week/)

### 4. EU AI Act 제50조 투명성 의무 발효, 생성형 AI 서비스에 표시 책임 부과
**카테고리:** Regulation / Compliance

**주요 내용:**
- EU AI Act의 제50조 투명성 의무가 8월 2일부터 발효됐다. AI와 상호작용하는 사용자 고지, 생성·조작된 콘텐츠의 표시 등 투명성 관련 책임이 사업자에게 부과된다.
- 위반 시 과징금은 글로벌 매출의 최대 3%에 이를 수 있어, EU 시장을 대상으로 하는 서비스에 실질적인 컴플라이언스 부담으로 작용한다.

**엔지니어 관점 포인트:**
제50조 발효는 모델 성능이 아니라 제품 설계와 배포 계층에 직접 영향을 주는 변화다. 챗봇이 AI임을 사용자에게 알리는 고지, 생성형 이미지·오디오·텍스트에 대한 기계 판독 가능한 표시 등은 백엔드가 아니라 UX와 출력 파이프라인에 녹여 넣어야 하는 요구사항이다. 매출의 3%라는 과징금 규모를 감안하면, EU 사용자를 대상으로 하는 제품 팀은 콘텐츠 출처 표시(provenance)와 워터마킹, 사용자 고지 UI를 로드맵의 후순위가 아니라 배포 전 필수 항목으로 다뤄야 한다. 이는 개발 단계에서부터 표시 메타데이터를 어떻게 생성·전파할지 설계에 반영해야 하는 문제다.

**관련 링크:** [LLM News August 2026](https://augusto.digital/insights/blogs/monthly-llm-news-august-2026/)
