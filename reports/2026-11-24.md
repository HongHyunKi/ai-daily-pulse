### 1. [Gemini API, 파일을 필요한 범위만 잘라 처리]
* **카테고리:** LLM API / 멀티모달 개발
* **주요 내용:**
  - Google이 11월 23일 Gemini API에 네이티브 파일 슬라이싱 컨트롤을 공개했습니다. PDF·Office/OpenDocument 문서는 페이지와 콘텐츠 레이어, 스프레드시트는 시트·셀 범위와 값·수식·시각 레이어, 오디오·비디오는 시간 구간과 프레임·오디오·트랜스크립트 레이어를 지정해 모델에 전달할 수 있습니다.
  - Files API로 파일을 한 번 업로드한 뒤 URI를 재사용할 수 있으며, Google은 지정한 부분만 토큰 과금 대상이라고 설명합니다. 기능은 Google AI Studio와 Gemini platform API에서 “available today” 상태로 제공되지만, 공식 발표는 GA 또는 Preview 라벨을 명시하지 않았습니다.
* **엔지니어 관점 포인트:**
  - 대용량 문서·표·미디어 파이프라인은 전체 파일을 매번 평탄화·렌더링·재업로드하는 대신 파일 URI와 페이지·셀·시간 범위를 조합하는 구조로 단순화할 수 있습니다. 이는 발표된 API 동작에 근거한 통합 추론입니다.
  - 기존 로컬 파서를 바로 제거하기보다 정확한 범위를 결정하기 쉬운 워크로드부터 토큰 사용량, 지연, 파일 제한, 응답 품질을 병행 검증해야 합니다.
* **관련 링크:** [Google 공식 발표](https://blog.google/innovation-and-ai/technology/developers-tools/file-slicing-controls/)

### 2. [Cisco·OpenAI, 에이전트가 만드는 Linux 런타임 방어막 Shirudo 공개]
* **카테고리:** 오픈소스 / 에이전트 보안 인프라
* **주요 내용:**
  - Cisco와 OpenAI가 11월 23일 Linux 실행 시스템을 에이전트가 방어하도록 설계한 오픈소스 프로젝트 Shirudo를 공개했습니다. eBPF 기반 프로그램을 실행 중인 커널에 적용해 재부팅이나 소스 수정 없이 임시 방어막을 배치하는 방향입니다.
  - 방어막은 암호학적으로 서명하고 호스트가 검증하도록 설계됐습니다. Cisco가 제시한 취약점 차단 결과는 자체 테스트 주장으로, 독립 재현이나 일반적인 차단율 보장으로 확대해서는 안 됩니다.
* **엔지니어 관점 포인트:**
  - 영구 패치 전 완화 계층과 에이전트 생성 런타임 정책을 실험할 수 있지만, eBPF 권한·커널 호환성·서명 키 관리·오탐 복구를 플랫폼 보안 운영에 포함해야 합니다.
  - GA나 상용 서비스가 아니라 프로젝트 공개 단계이므로, 운영 도입보다 격리된 Linux 환경에서 방어막 검증과 실패 복구 절차를 먼저 평가하는 것이 적절합니다.
* **관련 링크:** [Cisco 공식 발표](https://newsroom.cisco.com/c/r/newsroom/en/us/a/y2026/m11/cisco-and-openai-launch-shirudo-a-new-project-to-safeguard-agentic-ai.html) · [Shirudo GitHub](https://github.com/shirudo-dev/shirudo)

### 3. [OpenCode 2.4.x, 브라우저·자동화 기능과 후속 안정화 제공]
* **카테고리:** Developer Tool / 코딩 에이전트
* **주요 내용:**
  - OpenCode 2.4.0이 데스크톱 브라우저, 타이머·cron·MCP 이벤트 기반 자동화, 백그라운드 비디오 생성, 버전 범위 플러그인 자동 업데이트를 추가했습니다. 브라우저는 기존 Chrome·Edge·Firefox·Safari의 로그인과 방문 기록을 가져와 지속 프로필로 사용할 수 있습니다.
  - 같은 날 후속 2.4.1은 macOS 12의 메시지 저장, 설정만으로 구성한 provider 모델, 압축·캐시 비용 계산, 속도 선택기 표시 문제를 수정했습니다. 따라서 2.4.0의 기능을 쓰려는 사용자는 2.4.1부터 검토하는 편이 안전합니다.
* **엔지니어 관점 포인트:**
  - 인증된 브라우저 상태와 셸·MCP 이벤트를 에이전트에 연결하는 만큼 브라우저 프로필 격리, 확장 프로그램 출처, 이벤트 발행자, 자동화 권한을 별도 검토해야 합니다. 이는 기능 문서에서 도출한 운영 보안상 추론이며, 해당 릴리스가 악성 또는 취약하다는 뜻은 아닙니다.
  - 자동화가 셸 명령을 실행할 수 있는 조직은 승인 정책, 실행 로그·종료 코드 수집, 예약 작업의 변경 권한을 배포 전 점검해야 합니다.
* **관련 링크:** [OpenCode 공식 변경 내역](https://opencode.ai/changelog?area=core%2Cterminal) · [OpenCode v2.4.1 릴리스](https://github.com/anomalyco/opencode/releases/tag/v2.4.1)

### 4. [mcp-server-kubernetes, 원격 MCP 인자 주입 취약점 패치 필요]
* **카테고리:** 보안 / MCP 서버
* **주요 내용:**
  - CVE-2026-134817(GHSA-8v48-c263-r637)이 11월 22~23일 공개됐습니다. 4.2.0 미만 버전에서는 원격 MCP 클라이언트가 `exec_in_pod`, `kubectl_patch`, `kubectl_logs` 등의 위치 인자에 대시로 시작하는 값을 주입해 `kubectl` 플래그로 해석되게 만들 수 있으며, GitHub는 High·CVSS 7.1로 평가합니다.
  - 수정 버전은 플래그 형태의 위치 인자를 거부하고 관련 테스트를 추가했습니다. 공개 권고에는 패키지 메타데이터가 불완전하다고 적혀 있어 스캐너 결과만으로 판단하면 안 됩니다.
* **엔지니어 관점 포인트:**
  - 모든 배포의 실제 이미지·npm 패키지·빌드 버전을 확인하고 4.2.0 이상으로 업그레이드하세요. 수정 여부를 확인하기 전에는 SSE·Streamable HTTP 노출을 제한하거나 비활성화하는 조치가 필요합니다.
  - 권고는 취약한 동작을 설명하지만 실제 악용을 확인했다고 주장하지 않습니다. 대응의 우선순위는 패치, MCP 전송면 노출 점검, 호스트 권한 최소화입니다.
* **관련 링크:** [GitHub Advisory Database](https://github.com/advisories/GHSA-8v48-c263-r637) · [수정 커밋](https://github.com/Flux159/mcp-server-kubernetes/commit/588d4949b0233974c3966a7d24d532be11e56d0d)

### 5. [Gradio SSR 모드, Host 위조로 로컬 검사를 우회하는 취약점 공개]
* **카테고리:** 보안 / AI 앱 프레임워크
* **주요 내용:**
  - CVE-2026-134825(GHSA-4cx6-qfwr-9vfq)이 11월 22~23일 공개됐습니다. Gradio 6.27.0부터 6.32.0 미만에서 `ssr_mode`가 활성화된 경우 인증되지 않은 원격 요청이 `Host: localhost`를 위조해 SSR 루프백 검사를 우회할 수 있으며, GitHub는 High·CVSS 8.3으로 평가합니다.
  - 이 동작은 운영자 계정의 로컬 Hugging Face 토큰을 사용하는 실행 기록 작업과 저장소 열람·쓰기까지 연결될 수 있습니다. 공식 Gradio 6.32.0 릴리스에 해당 수정이 포함돼 있으므로, 새 릴리스 뉴스라기보다 이 기간에 공개된 취약점 공지가 핵심입니다.
* **엔지니어 관점 포인트:**
  - Gradio 배포를 최소 6.32.0으로 올리고, 인터넷 또는 비신뢰 네트워크에 노출된 `ssr_mode` 인스턴스를 식별하세요. 취약 버전이 노출됐다면 애플리케이션과 Hugging Face 활동 로그를 검토하고, 비인가 접근 정황이 있을 때 토큰을 회전하는 것이 좋습니다.
  - 권고는 실제 악용이나 토큰 값 유출을 확인했다고 말하지 않습니다. 따라서 침해를 단정하지 말고 노출 범위와 로그 증거에 따라 후속 조치를 결정해야 합니다.
* **관련 링크:** [GitHub Advisory Database](https://github.com/advisories/GHSA-4cx6-qfwr-9vfq) · [Gradio 6.32.0 릴리스](https://github.com/gradio-app/gradio/releases/tag/gradio@6.32.0)
