### 1. GitHub Agentic Workflows 정식 출시, Markdown으로 저장소 자동화 정의

* **카테고리:** Open Source / Agentic AI / Developer Tool
* **주요 내용:**
  - GitHub가 10월 28일 Agentic Workflows의 정식 출시를 발표했습니다. GitHub Next의 오픈소스 프로젝트로, 자연어로 작성한 Markdown 워크플로우를 GitHub Actions YAML로 컴파일해 실행합니다.
  - 이슈 분류, CI 실패 분석, 문서 수정과 테스트 작성처럼 상황 판단이 필요한 작업을 기존 Actions 환경에서 자동화할 수 있습니다. 기본 읽기 전용 권한, 샌드박스와 방화벽, 검증된 출력 처리 및 변경 적용 전 위협 탐지 단계를 제공합니다.
  - github.com의 Free·Team·Enterprise 플랜에서 사용할 수 있으며, 기본 실행 엔진인 Copilot CLI를 사용하려면 Copilot 라이선스가 필요합니다.
* **⚙️ 엔지니어 관점 포인트:**
  - 별도의 에이전트 운영 서버를 만들기 전에 기존 CI 환경에서 실패 원인 분석이나 이슈 분류부터 시험할 수 있습니다. 코드·문서 변경으로 확장할 때는 워크플로우의 쓰기 권한과 검토 절차를 함께 설계하는 편이 좋습니다.
* **🔗 관련 링크:** [GitHub 공식 발표](https://github.blog/changelog/2026-10-28-github-agentic-workflows-generally-available/)

### 2. GitHub Copilot Fusion 정식 출시, 작업에 따라 모델 선택·검토 조합

* **카테고리:** LLM / Developer Tool
* **주요 내용:**
  - GitHub가 10월 28일 Copilot Fusion을 정식 출시했습니다. 단일 모델을 실행하는 Single, 초안 품질을 확인해 필요하면 상위 모델로 전환하는 Cascade, 다른 모델이 결과를 검토하는 Critique 방식으로 모델을 선택하고 조합합니다.
  - 사용자는 Standard·High·Max 수준을 선택할 수 있습니다. 조직이나 기업에서 허용한 모델만 사용하며, 모든 Copilot 플랜의 VS Code, Copilot 앱·CLI, JetBrains IDE에서 제공합니다.
  - 실제 사용한 각 모델의 표준 요율을 적용합니다. 유료 플랜 대상 할인은 한시적이므로 할인 가격을 장기 운영비의 기준으로 삼아서는 안 됩니다.
* **⚙️ 엔지니어 관점 포인트:**
  - 작업마다 모델을 직접 고르는 부담을 줄일 수 있습니다. 다만 모델 전환이나 추가 검토가 비용·지연에 미치는 영향은 작업마다 다르므로, 반복되는 버그 수정과 코드 리뷰 사례로 단일 모델 대비 품질·소요 시간·비용을 함께 비교할 필요가 있습니다.
* **🔗 관련 링크:** [GitHub 공식 발표](https://github.blog/changelog/2026-10-28-route-and-orchestrate-models-with-github-copilot-fusion/)

### 3. Liquid AI, LFM3 공개 — 로컬 특화 작업을 겨냥한 소형 모델군

* **카테고리:** Open Weights / LLM / On-device AI
* **주요 내용:**
  - Liquid AI가 10월 27일 LFM3 모델군을 발표했습니다. 첫 공개는 약 2B 규모를 중심으로 텍스트·비전·오디오·옴니·의사결정 모델을 포함하며, 가중치를 내려받아 조정하고 배포할 수 있습니다.
  - 텍스트 모델 LFM3-1.7B의 공식 모델 카드에는 17.3억 파라미터, 입력과 출력을 합친 256K 토큰 컨텍스트, 한국어를 포함한 16개 언어가 명시되어 있습니다. 이 컨텍스트 사양을 다른 모달리티 모델에 그대로 적용해서는 안 됩니다.
  - GGUF와 MLX 등 로컬 실행용 변형을 제공하며 라이선스는 LFM Open License v1.0입니다. 제작사는 이 텍스트 모델을 도구 호출·구조화된 출력·도메인별 미세조정 용도로 설명하면서, 에이전트 코딩이나 복잡한 다단계 추론에는 권장하지 않는다고 명시했습니다.
* **⚙️ 엔지니어 관점 포인트:**
  - 범위가 분명한 도구 호출이나 문서 분류를 기기 안에서 처리하려는 팀의 실험 후보입니다. 범용 코딩 에이전트 대체를 전제하기보다 대상 업무의 정확도와 실제 기기에서의 메모리·응답 시간을 확인하고, 배포 전 라이선스 조건을 검토해야 합니다.
* **🔗 관련 링크:** [Liquid AI 공식 발표](https://www.liquid.ai/blog/lfm3), [LFM3-1.7B 공식 모델 카드](https://huggingface.co/LiquidAI/LFM3-1.7B)

### 4. Baidu, Unlimited OCR 2 공개 — 긴 문서의 페이지 간 맥락 처리 개선

* **카테고리:** Open Source / Document AI
* **주요 내용:**
  - Baidu가 10월 27일 MIT 라이선스의 Unlimited OCR 2와 초장문 문서 파싱 벤치마크 MarathonDocBench를 공개했습니다. 공식 모델 카드에는 10월 28일 ms-swift 학습 지원 소식도 추가됐습니다.
  - 핵심 기법인 SR-SWA는 텍스트와 시각 정보 간 어텐션이 참조하는 대상을 고정 크기 집합으로 압축합니다. 제작사는 이를 통해 문서가 길어져도 단계별 디코딩 지연과 메모리 사용량을 거의 일정하게 유지한다고 설명합니다.
  - 여러 페이지를 하나의 요청으로 처리하는 인터페이스와 Transformers·SGLang 실행 안내를 제공합니다. SGLang 안내에는 페이지 윈도우를 줄이면 최대 메모리 사용량은 낮아지지만, 윈도우 경계를 넘는 내용의 결합 품질이 떨어질 수 있다고 명시되어 있습니다.
* **⚙️ 엔지니어 관점 포인트:**
  - 페이지를 따로 OCR한 뒤 이어 붙이는 문서 수집 파이프라인에서, 페이지 사이로 이어지는 내용을 얼마나 잘 보존하는지 비교할 가치가 있습니다. 어텐션 최적화가 전체 처리 시간이나 이미지 전처리 메모리까지 일정하게 만든다는 뜻은 아니므로, 실제 문서 길이와 동시 요청 수에 맞춰 측정해야 합니다.
* **🔗 관련 링크:** [Baidu 공식 모델 카드 및 릴리스 기록](https://huggingface.co/baidu/Unlimited-OCR-2)
