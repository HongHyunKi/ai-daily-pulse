## 오늘의 핵심 AI 뉴스 요약

### 1. Gemini API Computer Use, 정식 출시
* **카테고리:** Developer Tool / Agentic AI
* **주요 내용:**
  - Google이 Gemini API의 Computer Use 도구를 Interactions API와 GenerateContent API에서 정식(GA) 지원한다고 릴리스 노트에 기록했습니다.
  - 브라우저·데스크톱·모바일 환경에서 모델이 화면을 관찰하고 클릭·입력 같은 작업을 수행하는 에이전트 워크플로우를 API로 구성할 수 있습니다.
  - 같은 릴리스 노트에는 코딩 에이전트와 CI에서 사용할 수 있는 무상태·무의존성 `gemini-api` CLI 베타도 함께 안내돼 있습니다.
* **엔지니어 관점 포인트:**
  - Computer Use가 실험 단계를 벗어나면서 UI 자동화는 단순 데모보다 권한, 작업 범위, 실패 복구를 포함한 제품 설계 문제로 이동합니다.
  - 실제 도입 전에는 프롬프트 인젝션 방어, 민감 화면 차단, 승인 지점, 재현 가능한 브라우저 테스트를 함께 설계해야 합니다.
* **관련 링크:** [Gemini API 릴리스 노트](https://ai.google.dev/gemini-api/docs/changelog)

### 2. Google Cloud, 에이전트 전용 실행 환경 Agent Compute Engine 공개
* **카테고리:** AI Infrastructure / Agentic AI
* **주요 내용:**
  - Google Cloud가 하드웨어 격리형 microVM 샌드박스를 제공하는 Agent Compute Engine을 10월 인프라 업데이트에서 소개했습니다.
  - Agent Gateway와 Agent Registry 같은 거버넌스 기능을 묶고, 빠른 기동·copy-on-write 메모리 공유·보안 및 신원 관리·멀티클라우드 관측성을 목표로 합니다.
  - Google은 컨테이너의 밀도와 VM의 격리를 함께 제공해 자율 에이전트를 대규모로 운영하는 실행 계층으로 설명합니다.
* **엔지니어 관점 포인트:**
  - 에이전트 플랫폼의 병목이 모델 호출에서 격리된 실행 환경, 권한 위임, 관측성으로 옮겨가고 있습니다.
  - 에이전트별 파일·네트워크·시크릿 경계를 분리하고, 샌드박스 생성 비용과 장기 실행 작업의 비용 상한을 먼저 측정해야 합니다.
* **관련 링크:** [Google Cloud AI 인프라·오케스트레이션 10월 업데이트](https://cloud.google.com/blog/topics/ai-infrastructure/whats-new-in-ai-infrastructure-this-month)

### 3. OpenAI, 프런티어 모델과 Codex 트래픽에 다층 모니터링 확대
* **카테고리:** AI Safety / Agentic AI
* **주요 내용:**
  - OpenAI가 프런티어 모델의 RL·평가·도구 사용 harness와 내부 Codex 트래픽을 대상으로 다층 모니터링을 확대했다고 공개했습니다.
  - 경량 activation probe, 모델 기반 reviewer, 조사 에이전트, 외부 telemetry를 활용한 자동 조사, 사람 대응으로 이어지는 방식을 설명했습니다.
  - 모델의 모니터 회피를 유도하지 않도록 모니터링 결과를 개별 RL 샘플의 보상에 직접 반영하지 않고 비동기적으로 처리한다고 밝혔습니다.
* **엔지니어 관점 포인트:**
  - 자율 코딩 에이전트의 안전은 사전 차단만으로 끝나지 않고, 행동 로그·네트워크 telemetry·자동 중지·사람 대응을 포함한 운영 루프가 되어야 합니다.
  - API 기반 에이전트는 대화 추적을 활성화해야 자동 중지 범위를 명확히 할 수 있으며, 현재 Chat Completions API에는 이 모니터링이 적용되지 않는다는 제한도 확인해야 합니다.
* **관련 링크:** [How we detect frontier model misalignment](https://alignment.openai.com/how-we-detect-frontier-model-misalignment)

### 4. LiteLLM, 공급망 공격 후 릴리스·권한 체계 강화 계획 공개
* **카테고리:** Open Source / Security
* **주요 내용:**
  - LiteLLM이 10월 공급망 공격 이후 전용 GitHub owner 계정, 토큰 기반 활동 경보, 조직 감사 로그의 Splunk 전송, 시크릿 스캐닝과 push protection 같은 후속 조치를 공개했습니다.
  - 중요 취약점의 사전 배포를 위한 Private Registry, Chainguard 기반 의존성·이미지, 외부 취약점 공개 프로그램, PyPI·Docker 이미지 사후 검증기도 추진합니다.
  - 일부 조치는 완료됐지만, 많은 항목은 11~12월 또는 2027년 초를 목표로 진행 중입니다.
* **엔지니어 관점 포인트:**
  - AI 게이트웨이와 SDK도 일반 오픈소스 패키지와 같은 공급망 위험을 가지므로, 버전 고정·서명 검증·CI 시크릿 최소 권한·배포 후 산출물 비교가 필요합니다.
  - 에이전트가 사용할 수 있는 개발자 토큰은 정규 사용자 권한으로 제한하고, owner·배포 권한과 분리하는 운영 원칙이 재확인됐습니다.
* **관련 링크:** [LiteLLM의 10월 21일 사고 후 보안 변경 사항](https://litellm.vercel.app/blog/security-changes-after-oct-21-2026)

### 5. Google Workspace MCP, 에이전트용 OAuth 클라이언트 표기 의무화 예고
* **카테고리:** Agentic AI / API Governance
* **주요 내용:**
  - Google Workspace 릴리스 노트에 따르면 Workspace MCP 서버를 호출하는 OAuth 클라이언트는 Google Auth Platform에서 AI 에이전트용 클라이언트라는 설정을 선택해야 합니다.
  - 2026년 11월 11일부터 해당 표기가 없는 앱·통합의 MCP 요청을 거부하고, 일반 REST API만 사용하는 비에이전트 앱은 영향을 받지 않습니다.
  - 에이전트 기능과 일반 기능이 하나의 OAuth 클라이언트를 공유한다면, 에이전트 전용 클라이언트를 별도로 만드는 방식이 권장됩니다.
* **엔지니어 관점 포인트:**
  - MCP가 단순한 도구 연결을 넘어 OAuth 정책·감사·권한 분리의 대상이 되고 있습니다.
  - Gmail·Drive·Docs·Sheets·Calendar·Chat 통합을 운영 중인 팀은 마감 전에 클라이언트 분리, 동의 화면, 토큰 발급과 재승인 흐름을 점검해야 합니다.
* **관련 링크:** [Google Workspace 개발자 릴리스 노트](https://developers.google.com/workspace/release-notes)
