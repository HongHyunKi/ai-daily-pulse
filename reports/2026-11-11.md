### 1. Google, Gemini 4 Carbon API 공개 — 장기 실행 에이전트와 고난도 코딩에 초점
* **카테고리:** LLM / Agentic AI / Developer Tool
* **주요 내용:**
  - Google이 11월 10일 Gemini 4 Carbon을 개발자와 기업에 공개했다. Google은 이 모델을 복잡한 소프트웨어 엔지니어링, 과학적 추론, 장기 실행 에이전트 워크플로우에 맞춘 최신 프런티어 모델로 소개한다.
  - 유료 Google AI Studio·Gemini API와 Gemini for business에서 사용할 수 있으며, 공개된 도입 가격은 입력 100만 토큰당 2달러, 출력 100만 토큰당 10달러다.
  - Google Antigravity에서는 하나의 요청을 여러 에이전트가 나눠 수행하는 `/swarm` 프리뷰를 제공한다. Carbon을 설계·조정·감사처럼 깊은 추론이 필요한 역할에 배치하고, 다른 모델과 격리된 작업공간에서 병렬 실행하는 방식이다.
* **엔지니어 관점 포인트:**
  - 단순 챗봇보다 긴 계획·검증 루프를 요구하는 코드 수정, 디버깅, 리서치 작업을 API 수준에서 비교할 수 있는 선택지가 늘었다. 기존 모델과 교체하기보다 실제 작업셋에서 성공률, 지연시간, 토큰 사용량을 함께 측정해야 한다.
  - `/swarm` 같은 다중 에이전트 실행은 병렬성보다 권한 경계와 변경 충돌 관리가 먼저다. 작업공간별 파일 격리, 검증 에이전트의 독립성, 실패 시 롤백을 테스트 항목으로 고정하는 편이 안전하다.
  - Google이 제시한 벤치마크·비용 우위는 공급자 자체 설명이므로, 운영 판단에는 자체 코드베이스와 고정된 프롬프트를 사용한 재현 측정이 필요하다.
* **관련 링크:** [Google: Gemini 4 Carbon is now available](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-carbon-now-available/), [Google Developers: Gemini 4 Carbon for developers](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-4-carbon-developers/)

### 2. Google, TPU 8tx·8i Max 공개 — 보안 추론과 백만 토큰 컨텍스트를 하드웨어 구성으로 분리
* **카테고리:** AI Infrastructure / Agentic AI
* **주요 내용:**
  - Google이 11월 9일 8세대 TPU 제품군에 TPU 8tx와 TPU 8i Max를 추가했다.
  - TPU 8tx는 민감한 데이터를 위한 하드웨어 수준의 보안·기밀 추론을, TPU 8i Max는 거대한 컨텍스트 윈도우와 랙당 높은 계산 밀도를 겨냥한다.
  - Google은 TPU를 PyTorch와 오픈소스 소프트웨어, 자동화 도구에서 더 쉽게 사용할 수 있도록 하겠다고 설명했다. 8t·8i·8tx·8i Max로 학습, 실시간 추론, 보안 추론, 대규모 컨텍스트라는 네 가지 구성을 제시한다.
* **엔지니어 관점 포인트:**
  - 에이전트 인프라의 차별화 지점이 GPU 종류 하나가 아니라 보안 모델, 메모리·네트워크 구성, 컨텍스트 크기 같은 시스템 설계로 이동하고 있다.
  - 백만 토큰 컨텍스트를 지원해도 실제 비용과 지연은 KV 캐시, 프리필, interconnect, 배치 방식에 좌우된다. 긴 문서를 무조건 한 번에 넣기보다 검색·요약·캐시 전략과 함께 벤치마크해야 한다.
  - 규제 데이터에 적용할 때는 ‘기밀 추론’이라는 제품 설명만으로 판단하지 말고 키 관리, 테넌트 격리, 로그·메모리 잔존 정책을 클라우드 계약과 구현 수준에서 확인해야 한다.
* **관련 링크:** [Google: Our newest TPUs: 8tx and 8i Max](https://blog.google/innovation-and-ai/infrastructure-and-cloud/global-network/tpu-8i-max-and-8tx/)

### 3. Meituan, LongCat-2.5 공개 — 1.6T 파라미터 멀티모달 MoE를 MIT 라이선스로 제공
* **카테고리:** Open Source / LLM / Agentic AI
* **주요 내용:**
  - Meituan LongCat 팀이 Hugging Face에 LongCat-2.5를 공개했다. 모델 카드는 총 1.6T 파라미터, 토큰당 약 48B 활성화 규모의 멀티모달 MoE 모델로 설명한다.
  - 시각 이해와 에이전트 코딩을 결합해 복잡한 코드베이스 개발, 전체 프로젝트 빌드, 크리에이티브 디자인, 3D 작업 같은 장기 실행 작업을 목표로 한다.
  - 모델 카드에는 MIT 라이선스, 장기 에이전트 RL, 멀티 교사 학습, 긴 시퀀스 학습 최적화가 명시돼 있다. 일부 자체 평가에서는 장문 SFT 작업의 디바이스당 처리량이 DDP 기준보다 86% 높았다고 보고한다.
* **엔지니어 관점 포인트:**
  - 오픈 웨이트 모델이 텍스트 생성뿐 아니라 시각 입력과 도구 기반 장기 작업을 기본 범위로 삼고 있다. 자체 호스팅·도메인 튜닝을 원하는 팀의 실험 선택지가 넓어진다.
  - 총 파라미터가 1.6T인 만큼 활성 파라미터 48B만 보고 단일 GPU 모델로 판단하면 안 된다. 가중치 저장, 병렬화, KV 캐시, 지원 런타임의 실제 비용을 먼저 계산해야 한다.
  - 모델 카드의 비교표에는 자체 측정값과 외부 보고값이 섞여 있으므로, 도입 전 동일한 도구·컨텍스트·실패 판정 기준으로 코드 에이전트 평가를 다시 실행해야 한다.
* **관련 링크:** [Hugging Face: Meituan LongCat-2.5 model card](https://huggingface.co/meituan-longcat/LongCat-2.5)

### 4. GitHub Copilot SDK 1.0.31 — 에이전트 샌드박스와 도구 오류 처리를 운영 수준으로 보강
* **카테고리:** Developer Tool / Agentic AI / 보안
* **주요 내용:**
  - GitHub가 11월 10일 Copilot SDK v1.0.31을 릴리스했다.
  - Windows 샌드박스에 경로 열거만 허용하는 `userPolicy.filesystem.enumeratePaths`를 추가했고, 도구 결과를 런타임에 전달하지 못하면 SDK가 오류를 기록하고 도구 호출에 오류 결과를 반환하도록 바꿨다.
  - 세션 생성·재개·도구 설정에서 같은 이름의 도구가 중복되면 어느 핸들러를 쓸지 임의로 선택하지 않고 명시적 오류를 낸다. MCP Apps도 렌더러가 설정된 경우에만 런타임이 광고하도록 조정됐다.
* **엔지니어 관점 포인트:**
  - 에이전트 SDK의 안정성 기준이 모델 응답 품질뿐 아니라 도구 실패를 유실하지 않는 것, 권한을 최소화하는 것, 도구 이름 충돌을 조기에 막는 것으로 확장되고 있다.
  - 기존 통합은 도구 호출 실패가 빈 응답이나 무응답으로 처리되는지, 동일한 도구명이 여러 서버에서 들어올 때의 동작이 무엇인지 회귀 테스트해야 한다.
  - 경로 열거 권한은 읽기 권한과 다르지만 파일 구조 자체가 민감정보가 될 수 있다. 샌드박스 정책을 추가할 때 허용 경로 목록과 텔레메트리 노출 범위를 함께 검토해야 한다.
* **관련 링크:** [GitHub Copilot SDK v1.0.31 release](https://github.com/github/copilot-sdk/releases/tag/v1.0.31)
