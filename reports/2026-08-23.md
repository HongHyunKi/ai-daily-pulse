### 1. Nvidia, 단일 GPU에서 돌아가는 오픈 모델 Nemotron 3.5 Lightning 공개
**카테고리:** Open Source / LLM

**주요 내용:**
- Nvidia가 3B 활성 파라미터를 쓰는 30B 규모의 MoE(Mixture-of-Experts) 오픈 모델 Nemotron 3.5 Lightning을 공개했다.
- 가중치와 학습 데이터, 학습 레시피까지 OpenMDW-1.1 허가형 라이선스로 함께 배포되어 별도 허가 없이 다운로드, 사용, 수정이 가능하다.
- H100 한 장 또는 DGX Spark(GB10) 한 대 수준의 단일 GPU에서 구동되도록 설계됐고, 동급 모델 대비 출력 속도는 최대 4배, 에이전트 작업 완료 속도는 30% 빠르다고 소개됐다.
- Hugging Face, ModelScope, OpenRouter, Nvidia 자체 채널에서 내려받을 수 있다.

**엔지니어 관점 포인트:**
Nemotron 3.5 Lightning은 하나의 거대 모델로 모든 작업을 처리하는 방식이 아니라, 멀티 에이전트 시스템 안에서 특정 역할을 맡는 경량 전문 모델을 지향한다. 활성 파라미터를 3B로 낮춘 MoE 구조 덕분에 상시 구동되는 에이전트 워크로드를 로컬 단일 GPU에서 감당할 수 있어, 추론 비용과 데이터 프라이버시가 걸림돌이던 온프레미스 배포의 선택지가 넓어진다. 학습 데이터와 레시피까지 공개된 점은 파인튜닝이나 도메인 특화 재현이 필요한 팀에게 실질적인 이점이며, 여러 소형 전문 모델을 라우터로 조합하는 아키텍처 실험을 앞당길 수 있다.

**관련 링크:** [CNBC](https://www.cnbc.com/2026/08/11/nvidia-releases-nemotron-3point5-lightning-open-source-ai-model-.html), [MarkTechPost](https://www.marktechpost.com/2026/08/11/nvidia-ai-releases-nemotron-3-5-lightning-and-nemo-switchyard/)

### 2. DeepSeek V4-Pro 정식 출시, 에이전트 특화와 시간대별 API 요금제 도입
**카테고리:** LLM

**주요 내용:**
- DeepSeek가 8월 13일 플래그십 모델 V4-Pro(빌드 0813)를 프리뷰에서 정식(GA) 단계로 전환했다.
- 작업 복잡도에 따라 연산량을 조절하는 적응형 추론을 도입해 low, standard, maximum 세 가지 추론 모드를 선택할 수 있다.
- 최대 100만 토큰 컨텍스트와 최대 38만 4천 토큰 출력, thinking/non-thinking 모드를 지원한다.
- 8월 16일부터 피크와 오프피크를 나눈 시간대별 API 요금제가 적용되며, 오프피크 단가는 피크의 절반으로 책정됐다.

**엔지니어 관점 포인트:**
V4-Pro의 핵심은 모델 자체가 도구 호출, 코드 실행, 다단계 워크플로우 같은 에이전트 작업에 맞춰졌다는 점이다. 추론 모드를 코드에서 직접 지정할 수 있어, 단순 조회는 저비용 모드로 처리하고 복잡한 문제만 최대 추론을 쓰는 식의 비용 최적화가 애플리케이션 레벨에서 가능해진다. 특히 오프피크 반값 요금제는 야간 배치나 대량 오프라인 처리 파이프라인의 운영비 구조를 다시 계산하게 만드는 변수다. 다만 벤치마크 수치는 아직 독립 검증이 필요한 단계이므로, 도입 전 자체 워크로드 기준의 실측이 권장된다.

**관련 링크:** [DeepSeek API Docs](https://api-docs.deepseek.com/news/news260813/), [Unite.AI](https://www.unite.ai/deepseek-ships-v4-pro-as-its-flagship-model-leaves-preview/)

### 3. Microsoft Agent Framework, BUILD 2026에서 Agent Harness와 Hosted Agents 정식 공개
**카테고리:** Agentic AI / Developer Tool

**주요 내용:**
- Microsoft가 BUILD 2026에서 Agent Framework(MAF)의 Agent Harness와 Hosted Agents를 정식(GA) 단계로 올리고 CodeAct 기능을 함께 소개했다.
- Agent Harness는 셸과 파일시스템 접근, 사람 승인(human-in-the-loop) 흐름, 장기 세션의 컨텍스트 관리를 프레임워크 기본 패턴으로 제공한다.
- CodeAct는 모델이 짧은 Python 프로그램 하나를 작성해 call_tool로 도구를 호출하고 샌드박스에서 한 번에 실행한 뒤 결과를 통합해 반환하는 방식으로, 격리된 Hyperlight 마이크로 VM에서 실행된다.
- Hosted Agents는 에이전트 코드를 컨테이너로 패키징해 Foundry가 관리하는 인프라에 배포하는 옵션이다.

**엔지니어 관점 포인트:**
그동안 에이전트 프레임워크의 약점은 프로토타입은 쉽지만 프로덕션에 올리는 순간 실행 격리, 승인 흐름, 장기 컨텍스트 관리 같은 문제를 팀마다 직접 재발명해야 한다는 점이었다. Agent Harness는 바로 이 운영 계층을 표준화해 에이전트를 실제 서비스로 올리는 문턱을 낮춘다. CodeAct 방식은 도구를 개별 호출로 여러 번 왕복하는 대신 코드 한 편으로 묶어 실행하기 때문에 지연과 토큰 소모를 줄일 수 있고, VM 단위 격리로 임의 코드 실행의 위험도 통제한다. .NET과 Python에서 동일한 개념과 API를 쓴다는 점은 기존 엔터프라이즈 스택과의 통합 부담을 낮추는 요소다.

**관련 링크:** [Microsoft DevBlogs](https://devblogs.microsoft.com/agent-framework/microsoft-agent-framework-at-build-2026-announce/), [InfoQ](https://www.infoq.com/news/2026/08/agent-framework-harness-ga/)

### 4. Meta, 첫 터미널 코딩 에이전트 Muse Code 베타 공개
**카테고리:** Developer Tool

**주요 내용:**
- Meta가 첫 터미널 기반 코딩 에이전트 Muse Code를 베타로 내놨다. 기반 모델은 Muse Spark 1.2다.
- 백그라운드에서 비동기로 유지되는 서브에이전트를 지원해 장기 작업을 병렬로 진행할 수 있다.
- /plan, /grill, /goal 같은 스킬을 기본 번들로 제공하며 macOS와 Linux를 지원한다.

**엔지니어 관점 포인트:**
터미널 네이티브 코딩 에이전트 영역은 이미 Claude Code, Codex CLI 등이 경쟁하고 있는데, Meta의 진입은 이 방식이 IDE 플러그인을 넘어 사실상의 표준 워크플로우로 자리잡고 있음을 보여준다. 특히 지속되는 비동기 서브에이전트는 리팩터링이나 대규모 마이그레이션처럼 오래 걸리는 작업을 백그라운드로 돌리면서 개발자는 다른 일을 병행하는 패턴을 가능하게 한다. /plan, /grill, /goal 같은 스킬을 기본 제공하는 방식은 에이전트 사용법을 팀 전반에 표준화하려는 시도로 읽히며, 조직 차원의 도입 시 학습 곡선을 낮추는 데 기여할 수 있다.

**관련 링크:** [Shakudo - Best AI Coding Assistants](https://www.shakudo.io/blog/best-ai-coding-assistants)

### 5. Z.AI, GLM-5.2 Turbo 공개하며 8월 모델 출시 경쟁 이어가
**카테고리:** LLM

**주요 내용:**
- Z.AI가 8월 17일 GLM-5.2 Turbo를 공개하며 이번 달 가장 최근 출시 모델에 이름을 올렸다.
- 8월 한 달 동안 7개 제공사에서 12개 이상의 신규 모델이 쏟아지는 흐름 속에서 등장했다.
- 같은 기간 Gemini 3.7 Flash, Qwen3.8-Max, Seed 2.1 Turbo 등 속도와 비용을 강조한 turbo/flash 계열 모델이 잇따라 발표됐다.

**엔지니어 관점 포인트:**
8월의 출시 목록을 관통하는 키워드는 turbo, flash, lightning처럼 속도와 단가를 앞세운 이름들이다. 이는 프런티어 성능 경쟁이 어느 정도 수렴하면서 시장의 무게추가 같은 품질을 더 싸고 빠르게 제공하는 쪽으로 이동하고 있음을 시사한다. 애플리케이션을 만드는 입장에서는 특정 모델에 고정하기보다, 라우팅 계층을 두고 작업 난이도에 따라 turbo급과 프런티어급을 오가며 비용과 지연을 조절하는 설계가 점점 합리적인 선택이 되고 있다.

**관련 링크:** [LLM Gateway Timeline](https://llmgateway.io/timeline)

## 오늘의 트렌드 한눈에 보기

이번 주 흐름을 하나로 묶으면 결국 에이전트의 실전 투입과 비용 효율화다. Nvidia의 Nemotron 3.5 Lightning과 DeepSeek V4-Pro는 모두 멀티 에이전트 워크로드를 겨냥하면서, 하나는 단일 GPU에서 돌아가는 경량 오픈 모델로, 다른 하나는 추론량을 조절하는 적응형 모델과 시간대별 요금제로 운영비 문제를 정면으로 다룬다. Microsoft Agent Framework의 Harness와 Hosted Agents 정식 공개, 그리고 Meta의 터미널 코딩 에이전트 Muse Code는 에이전트를 프로토타입 단계에서 프로덕션과 일상 개발 워크플로우로 끌어내리는 인프라 성숙을 보여준다. 여기에 turbo와 flash 계열 모델이 줄지어 나오는 상황까지 겹치면서, 개발자에게 던져지는 질문은 어떤 모델이 가장 똑똑한가에서 어떤 조합을 어떤 비용으로 운영할 것인가로 옮겨가고 있다.
