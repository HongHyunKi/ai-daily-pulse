### 1. VS Code 1.148, 에이전트 호스트와 격리 실행을 확장
* **카테고리:** AI 코딩 에이전트 / IDE / 원격 개발
* **주요 내용:**
  - 11월 25일 Stable 릴리스에서 Agent Host Protocol 1.1.0을 도입해 TCP 포트 포워딩·윈도잉, 세션 간 채팅 이동, 채팅별 harness 선택, Skills over MCP, 부분 읽기, HTTPS 상호운용을 지원한다.
  - 원격 에이전트의 worktree 정리, 호스트별 sandbox profile, 에이전트 세션용 격리 Linux Dev Container 생성을 추가했다. 에이전트 작업 중 호스트 절전 방지 기능은 프리뷰다.
  - Copilot harness의 셸 비밀번호 프롬프트를 채팅에 표시할 수 있으며, 입력값은 프로그램으로만 전달되고 모델에는 전송되지 않는다고 명시했다.
* **엔지니어 관점 포인트:**
  - 원격 코딩 에이전트의 작업공간 격리·정리·프로토콜 상호운용이 제품 내 기능으로 이동해 자체 오케스트레이션 코드를 줄일 수 있다.
  - sandbox와 Dev Container는 실험 기능이고 Local harness는 2027년 2월 제거 예정이므로, 운영 도입 전 호스트별 검증과 마이그레이션 계획이 필요하다. GitHub 화면은 분 단위 시각만 보여 주므로 초 단위·시간대는 연결된 REST API로 재확인해야 한다.
* **관련 링크:** [VS Code 1.148 릴리스 노트](https://code.visualstudio.com/updates/v1_148)

### 2. llama.cpp 1.1.0, 로컬 추론을 멀티모달·에이전트 서버로 확장
* **카테고리:** 오픈소스 / LLM 추론 / 로컬 에이전트
* **주요 내용:**
  - 새 모델과 TTS·오디오 모델 지원을 넓히고, 웹 UI를 Llama Chat으로 개편해 음성 메시지·받아쓰기·에이전트 trace를 제공한다.
  - 서버가 OpenAI 형식의 named `tool_choice`, 단일 모델용 `GET /models/sse`, 에이전트·MCP 프록시 플래그, MCP 도구의 이미지·오디오 결과를 지원한다.
  - C API의 기존 `llama_batch`는 `llama_batch_ext`와 `llama_process` 방향으로 폐기 예정이며, DFlash API와 GGUF 문자열 배열 메타데이터 접근도 추가됐다.
* **엔지니어 관점 포인트:**
  - 로컬 모델을 OpenAI 호환 에이전트·도구 호출·멀티모달 파이프라인에 연결하기 쉬워졌지만, 백엔드와 모델별 호환성·성능은 별도 검증해야 한다.
  - C/C++ 통합자는 `llama_batch` 사용처를 점검해야 한다. 릴리스 API 시각은 GitHub REST의 UTC `published_at`으로 확인되며, 기존 b12732 항목과는 다른 정식 1.1.0 릴리스다.
* **관련 링크:** [llama.cpp 1.1.0 릴리스](https://github.com/ggml-org/llama.cpp/releases/tag/v1.1.0)

### 3. Qwen Code 0.28.7, 장기 실행 에이전트와 도구 루프 정책을 재설계
* **카테고리:** 코딩 에이전트 / Agent Runtime / Breaking Change
* **주요 내용:**
  - CLI를 Harness kernel에서 실행하고, 모델별 reasoning effort·context window와 workspace별 worktree snapshot을 재실행 후에도 복원한다.
  - 관리형 Web Terminal 티켓을 SQL에 저장해 여러 control-plane 인스턴스가 WebSocket 업그레이드를 처리하면서 일회성·클러스터 한도를 유지하도록 했다.
  - **Breaking change:** TUI·headless·daemon 전반에서 모델 루프 감지와 tool-call 상한을 제거해 도구 결과와 오류를 모델에 그대로 전달한다.
* **엔지니어 관점 포인트:**
  - 승인 대기·재시작·호스팅 환경을 포함한 장기 세션의 복원성과 수평 확장성이 좋아진다.
  - 기존 암묵적 안전장치에 의존한 무인 실행은 위험해질 수 있으므로, 호출자 측에 단계·시간·비용 예산과 승인 정책을 명시적으로 추가해야 한다. 릴리스 시각은 GitHub 페이지의 분 단위 표시와 프로젝트 미러가 일치하며, 초 단위는 GitHub REST API로 확인하는 것이 안전하다.
* **관련 링크:** [Qwen Code 0.28.7 릴리스](https://github.com/QwenLM/qwen-code/releases/tag/v0.28.7)

### 4. Pydantic AI 2.75.0과 Pax/Harness 베타, 프레임워크를 터미널 에이전트로 연결
* **카테고리:** Agent Framework / Python / Coding Agent
* **주요 내용:**
  - Pydantic의 공식 터미널 코딩 에이전트 Pax를 Harness SDK 위에 제공하며, 샌드박스·MCP·Logfire tracing·플러그인을 사용하고 `--agent`로 사용자의 Pydantic AI 에이전트를 실행할 수 있다.
  - 2.75.0은 `RepoContext`·`Skills`·`Memory`에서 낮은 권한의 workspace 콘텐츠가 모델 지침에 직접 들어가지 않도록 하는 호환성 동작과, 비어 있거나 읽을 수 없는 응답을 fallback 경로로 넘길 수 있는 예외를 추가했다.
  - Pax의 지연 승인 핸들러는 resume token을 사용하는 방식으로 바뀌었다. PyPI 배포물은 GitHub Actions와 커밋에 연결된 provenance를 제공한다.
* **엔지니어 관점 포인트:**
  - 하나의 에이전트를 서비스·CLI·코드 통합에서 재사용하면서 승인·샌드박스·추적을 조합할 수 있어, 프레임워크와 코딩 도구 사이의 경계가 좁아진다.
  - Harness는 **베타**이고 API가 바뀔 수 있다. 업그레이드 전 prompt-injection 경계, fallback 예외 처리, 사용자 정의 승인 핸들러를 테스트해야 하며, 발표 글의 벤치마크 수치는 공급자 자체 주장으로 취급해야 한다.
* **관련 링크:** [Pydantic AI 2.75.0 릴리스](https://github.com/pydantic/pydantic-ai/releases/tag/v2.75.0)

### 5. `create-ai-agent-setup` npm 악성 패키지, 설치 호스트를 완전 침해로 간주해야
* **카테고리:** 공급망 보안 / npm / AI 에이전트
* **주요 내용:**
  - OSV 기록이 `create-ai-agent-setup`의 `2.0.0-alpha.0`, `2.0.0`, `2.1.0`을 악성 코드로 분류하고 GHSA-4c46-v99r-6h9r를 연결했다. 현재 패치 버전은 기록되어 있지 않다.
  - OSV의 게시 시각은 2026-11-25 21:43:16 UTC, 즉 11월 26일 06:43:16 KST로 윈도우 안에 있다. 기록은 CWE-506(내장 악성 코드)와 패키지 지표 해시도 제공한다.
  - GitHub Advisory의 대응 지침은 해당 패키지를 설치하거나 실행한 컴퓨터를 완전히 침해된 것으로 보고, 깨끗한 장비에서 비밀값·키를 교체하고 패키지를 제거하라는 것이다. 제거만으로 모든 악성 변경이 사라진다고 보장하지 않는다.
* **엔지니어 관점 포인트:**
  - npm lockfile·캐시·CI artifact·설치된 의존성 트리에서 패키지명과 세 버전을 즉시 검색하고, 발견 시 러너·호스트 격리와 clean-room 재빌드를 우선해야 한다.
  - 이 기록은 악성 분류와 영향 버전을 입증하지만, 실제 침해 규모나 전체 payload를 독립적으로 재현한 분석은 아니다. 따라서 노출 여부는 로컬 포렌식과 비밀값 사용 이력으로 확인해야 한다.
* **관련 링크:** [OSV 취약점 기록](https://osv.dev/vulnerability/MAL-2026-20623)
