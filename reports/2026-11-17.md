### 1. GitHub Copilot 주간 릴리스 — 모델 비교와 에이전트 세션 관리 강화
* **카테고리:** Developer Tool / Agentic AI
* **주요 내용:**
  - 11월 16일 공개된 주간 업데이트에서 GitHub Enterprise Server 저장소를 Copilot 앱에서 다루는 기능이 일반 제공으로 전환됐다.
  - Copilot 앱은 모바일에서 클라우드·Codespace 세션을 이어서 작업하고, 재인증이 필요한 MCP 서버를 대화 안에서 다시 연결할 수 있게 됐다.
  - VS Code 1.146에서는 에이전트가 여러 모델을 비교하고 결과를 요약하는 실험 기능, 모든 워크스페이스의 세션을 한눈에 관리하는 Inbox 모드가 추가됐다. Local harness는 2027년 2월 제거 예정이며 Copilot harness로의 이전이 안내됐다.
* **엔지니어 관점 포인트:**
  - 에이전트 IDE의 중심이 단일 채팅창에서 세션 큐·모델 평가·MCP 재인증을 포함한 작업 운영 화면으로 이동하고 있다.
  - 팀 표준 환경은 모델 비교 기능의 결과보다 권한, 세션 재개, harness 전환 시의 도구 호출 차이를 회귀 테스트해야 한다.
* **관련 링크:** [GitHub Copilot weekly releases — November 9](https://github.blog/changelog/2026-11-16-github-copilot-weekly-releases-november-9/)

### 2. GitHub Copilot 일부 모델 지원 종료 적용 — 모델 ID 고정 워크플로 점검 필요
* **카테고리:** LLM / Developer Tool / Model Lifecycle
* **주요 내용:**
  - GitHub가 11월 16일부터 대부분의 Copilot 경험에서 Claude Opus 4.8, Claude Opus 5, GPT-5.6 Terra를 지원 종료했다.
  - 대체 모델로 Claude Opus 5.5, GPT-6.1 Sol 또는 GPT-6 Luna가 제시됐고, Business·Enterprise에서는 기본 모델 정책에 따라 대체 모델이 자동 활성화될 수 있다.
  - Claude Opus 5는 모델 선택기에서 제거됐지만, 기존 권한이 있는 런타임 거부(fallback) 경로에서는 남아 있을 수 있다.
* **엔지니어 관점 포인트:**
  - 모델 교체는 이름 변경이 아니라 출력 형식, 도구 호출, 비용, 지연시간, 안전 정책이 달라지는 운영 변경이다. 평가 프롬프트와 구조화 출력 검증을 다시 돌려야 한다.
  - Copilot 기반 자동화와 문서에 모델명을 직접 고정했다면 지원 모델 정책과 대체 모델의 실패율·비용·품질을 함께 기록하는 것이 안전하다.
* **관련 링크:** [GitHub Copilot models deprecated on November 16, 2026](https://github.blog/changelog/2026-11-16-github-copilot-models-deprecated-on-november-16-2026/)

### 3. Hugging Face와 OpenRouter 결합 — 오픈웨이트 모델 호출이 다중 프로바이더 라우팅으로 전환
* **카테고리:** Open Source / LLM Infrastructure / Developer Tool
* **주요 내용:**
  - Hugging Face가 11월 16일부터 언어 모델용 Inference Providers의 자체 라우터를 OpenRouter 기반으로 전환했다.
  - 같은 Hugging Face 토큰과 API로 80개 이상의 프로바이더가 제공하는 모델을 호출할 수 있고, 라우터가 실시간 가격·속도·신뢰도에 따라 프로바이더를 선택하고 실패 시 재시도한다.
  - OpenAI Chat Completions·Responses API와 Anthropic Messages API 호환 경로가 제공되지만, 언어 모델 요청에서는 자체 프로바이더 키를 사용할 수 없게 되는 변경이 포함됐다.
* **엔지니어 관점 포인트:**
  - 오픈웨이트 모델 선택이 모델 파일을 직접 운영하는 문제에서, 품질·가격·지연시간·가용성을 기준으로 실행 프로바이더를 라우팅하는 운영 문제로 확장됐다.
  - 기존에 자체 키나 특정 프로바이더에 의존했다면 청구 주체, 데이터 경로, 리전, 재시도에 따른 중복 실행과 프롬프트 캐시 세션 ID를 확인해야 한다.
* **관련 링크:** [Hugging Face and OpenRouter join forces to make open-weight models easy to run](https://huggingface.co/blog/openrouter)

### 4. llama.cpp 팀, GitHub Actions 한계를 넘는 CI 구조 공개 — 캐시와 실행 컴퓨트를 분리
* **카테고리:** Open Source / Developer Tool / CI Infrastructure
* **주요 내용:**
  - ggml-org가 11월 16일 llama.cpp의 대규모 CI 개선 사례를 공개했다. 100개가 넘는 작업과 다양한 하드웨어 백엔드를 검증하는 프로젝트에서 GitHub Actions만으로는 캐시 용량과 러너 동시성이 병목이 됐다.
  - PR과 master 워크플로를 분리하고, 컴파일 캐시를 Hugging Face Buckets에 저장하며, Linux x64 작업 일부를 Hugging Face Jobs로 옮겼다.
  - 기존 GitHub Actions를 주 오케스트레이터로 유지하면서 `jobs-actions`를 다른 실행 환경으로 보내는 경량 브리지로 사용했다.
* **엔지니어 관점 포인트:**
  - 모델·커널·하드웨어 조합이 많은 AI 프로젝트에서는 소스 관리, 캐시 저장소, CPU/GPU 실행 환경을 분리하는 것이 CI 비용과 대기 시간을 줄이는 핵심 설계가 된다.
  - 외부 실행 환경을 붙일 때는 캐시 무결성, 비밀 전달 범위, 재현 가능한 이미지·러너 라벨, PR과 master의 권한 차이를 먼저 고정해야 한다.
* **관련 링크:** [How we optimized our workflows and overcame GitHub Actions limitations](https://huggingface.co/blog/ggml-org/llama-cpp-ci-buckets)

### 5. GitHub AI Scan, 최대 20개 저장소 일괄 시작 지원 — Copilot 없이도 AI 보안 분석 가능
* **카테고리:** AI Security / Developer Tool
* **주요 내용:**
  - GitHub가 11월 16일 조직 단위에서 최대 20개 저장소의 AI Scan을 한 번에 시작하는 기능을 공개 프리뷰로 추가했다.
  - AI Scan은 기본 브랜치에서 CodeQL이 지원하지 않는 언어의 취약점을 찾고, CodeQL이 분석하는 언어에서도 추가 이슈를 찾아 코드 스캐닝 백로그에 함께 표시한다.
  - GitHub Copilot 라이선스가 없어도 사용할 수 있으며, github.com과 데이터 레지던시를 지원하는 GitHub Enterprise Cloud에서 제공된다.
* **엔지니어 관점 포인트:**
  - AI 기반 보안 분석이 개별 저장소 실험에서 조직 단위의 반복 가능한 보안 운영으로 이동하고 있다.
  - 일괄 활성화 전에는 오탐률, 민감 코드의 처리·보존 정책, 기존 CodeQL과의 중복, PR 차단 기준을 정하고 작은 저장소 묶음으로 품질을 측정해야 한다.
* **관련 링크:** [Bulk start AI Scan for repositories](https://github.blog/changelog/2026-11-16-bulk-start-ai-scan-for-repositories/)

## 오늘의 트렌드 한눈에 보기
- 개발자 AI의 경쟁축이 모델 성능만이 아니라 세션 관리, 모델 비교, harness 전환, MCP 재인증 같은 에이전트 운영 경험으로 넓어지고 있다.

- 오픈소스 AI 인프라는 단일 저장소의 코드뿐 아니라 캐시, 실행 컴퓨트, 하드웨어 백엔드를 분리한 CI 설계까지 제품 경쟁력에 포함하고 있다.
