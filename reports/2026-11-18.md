## 오늘의 핵심 AI 뉴스 요약

### 1. Microsoft Ignite, 에이전트 운영과 코딩 모델을 한 플랫폼으로 묶다
* **카테고리:** LLM / Developer Tool / Agentic AI
* **주요 내용:**
  - Microsoft가 Ignite 2026에서 에이전트 코딩 모델 `Code 2`와 `Code 2 Flash`를 공개하고, GitHub Copilot과 Microsoft Foundry에서 일반 제공한다고 발표했다.
  - `Code 2`는 멀티파일 구현·저장소 단위 추론·디버깅을, `Code 2 Flash`는 코드 설명·부분 수정·반복 작업을 겨냥한다.
  - Microsoft는 에이전트 활동을 관찰·관리하는 `Agent 365 Business Analytics`와 AI 투명성 이니셔티브도 발표했다. NIST Agent Standards Initiative 협력을 포함한 표준화가 핵심 축이다.
* **엔지니어 관점 포인트:**
  - 코딩 모델을 고르는 문제와 에이전트의 권한·비용·감사 로그를 운영하는 문제가 하나의 플랫폼 설계로 합쳐지고 있다.
  - 모델 성능 비교만 하지 말고, 작업별 모델 라우팅·토큰 비용·도구 호출 감사·실패 시 human-in-the-loop 경로를 함께 평가해야 한다.
* **관련 링크:** [Ignite 2026: Building the frontier ecosystem](https://blogs.microsoft.com/blog/2026/11/17/ignite-2026-building-the-frontier-ecosystem/)

### 2. GitHub Copilot Fusion 확대 — 멀티모델 에이전트가 모바일과 Visual Studio로 확장
* **카테고리:** Developer Tool / Agentic AI / LLM Evaluation
* **주요 내용:**
  - GitHub가 Copilot Fusion을 github.com, Visual Studio, GitHub Mobile 베타로 확대하고, 작업별로 모델을 선택·조정하는 기능을 추가했다.
  - Claude Sonnet 5.5, GPT-6.1 Terra, MAI-Code-2가 Fusion 계층에 추가됐다.
  - GitHub가 공개한 Terminal-Bench 4.1 결과에서 Copilot Fusion Max는 71.2% 해결률을 기록했으며, GitHub는 일부 경쟁 모델 대비 비용 우위를 함께 제시했다.
* **엔지니어 관점 포인트:**
  - 단일 모델 선택기보다 작업별 모델 오케스트레이션이 기본 UX가 되면, 개발팀은 모델 이름보다 harness·도구 권한·평가 데이터의 일관성을 관리해야 한다.
  - 벤치마크 수치는 공급자 발표치이므로 내부 저장소와 실제 도구 체인에서 성공률, 재시도율, 지연시간, 비용을 별도로 측정해야 한다.
* **관련 링크:** [GitHub Copilot Fusion updates: more availability, benchmarks, and models](https://github.blog/changelog/2026-11-17-github-copilot-fusion-updates-more-availability-benchmarks-and-models/)

### 3. GPT-6.2 Astra·Sol, GitHub Copilot에 일반 제공
* **카테고리:** LLM / Developer Tool
* **주요 내용:**
  - OpenAI의 GPT-6.2 Astra와 GPT-6.2 Sol이 GitHub Copilot의 Pro+, Max, Business, Enterprise 사용자에게 순차적으로 제공된다.
  - Astra는 복잡한 에이전트 코딩과 터미널 작업, Sol은 복합적인 코딩·코드 리뷰·일상적인 에이전트 작업을 겨냥한다.
  - VS Code, Visual Studio, Copilot CLI, 코딩 에이전트, github.com, JetBrains, Xcode, Eclipse 등 여러 클라이언트에서 모델을 선택할 수 있다.
* **엔지니어 관점 포인트:**
  - 모델이 여러 클라이언트에 동시에 노출되면 조직 정책, 사용량 기반 과금, 점진적 rollout, 모델별 구조화 출력과 도구 호출 회귀 테스트가 중요해진다.
  - “더 많은 이슈를 더 적은 토큰으로 찾았다”는 초기 테스트 결과는 공급자 주장인 만큼, 실제 코드베이스에서 보안·정확성·리뷰 피로도를 함께 검증해야 한다.
* **관련 링크:** [OpenAI's GPT-6.2 Astra and GPT-6.2 Sol now available](https://github.blog/changelog/2026-11-17-openais-gpt-6-2-astra-and-gpt-6-2-sol-now-available/)

### 4. Copilot 코드 리뷰에 적응형 노력 수준과 비정형 시크릿 탐지 추가
* **카테고리:** Developer Tool / AI Security
* **주요 내용:**
  - Copilot 코드 리뷰가 PR의 복잡도와 위험도를 보고 Lite·Balanced·Max 중 리뷰 수준을 자동 선택하는 Adaptive 기능을 공개 프리뷰로 추가했다.
  - 공개 저장소에서는 관련 저장소의 코드·문서·custom instructions까지 참고하는 cross-repository context를 사용할 수 있다.
  - 500개가 넘는 알려진 시크릿 패턴과 형식이 뚜렷하지 않은 비밀번호·자격 증명을 AI 모델로 탐지하는 secret detection도 공개 프리뷰로 제공된다. Azure Repos용 Copilot 코드 리뷰는 일반 제공으로 전환됐다.
* **엔지니어 관점 포인트:**
  - AI 리뷰를 모든 PR에 같은 강도로 적용하는 대신 위험 기반으로 비용과 깊이를 조절할 수 있지만, 자동 선택 결과가 병합 차단 정책을 대신해서는 안 된다.
  - 시크릿 탐지는 기본적으로 꺼져 있고 변경분 중심으로 동작하므로, 사전 커밋·CI·이력 스캔과 중복·누락을 점검하고 오탐 처리 절차를 마련해야 한다.
* **관련 링크:** [Copilot code review: Adaptive effort, secret detection, and more](https://github.blog/changelog/2026-11-17-copilot-code-review-adaptive-effort-secret-detection-and-more/)

### 5. Vercel AI Gateway에서 GPT-6.2 모델과 에이전트용 API 경로 제공
* **카테고리:** Developer Tool / LLM Infrastructure
* **주요 내용:**
  - Vercel AI Gateway가 `openai/gpt-6.2-astra`와 `openai/gpt-6.2-sol`을 추가하고, 두 모델을 Responses API에서도 사용할 수 있게 했다.
  - Fast mode와 OpenAI Ultrafast 서비스 티어를 provider 옵션으로 요청할 수 있으며, Vercel CLI 설정을 통해 Codex·Cursor 등 코딩 에이전트에서 모델을 선택하는 경로를 안내했다.
  - Astra는 복잡한 멀티스텝 프로젝트, Sol은 일상적인 코딩·작성·에이전트 워크플로우를 대상으로 한다.
* **엔지니어 관점 포인트:**
  - 게이트웨이 계층은 모델 교체와 프로바이더 옵션을 애플리케이션에서 분리하는 데 유리하지만, Responses API의 도구 호출·스트리밍·서비스 티어 동작을 직접 회귀 테스트해야 한다.
  - 모델 ID만 바꿔도 비용과 지연시간이 달라질 수 있으므로, 라우팅 규칙과 함께 요청별 모델·서비스 티어·실패율을 관측 가능하게 남겨야 한다.
* **관련 링크:** [GPT-6.2 Astra and Sol now available on AI Gateway](https://vercel.com/changelog/gpt-6-2-astra-and-sol-now-available-on-ai-gateway)

## 오늘의 트렌드 한눈에 보기
- 개발자 AI의 경쟁은 더 좋은 모델 하나를 고르는 단계에서, 작업별 모델 라우팅·에이전트 harness·비용·감사 로그를 함께 운영하는 단계로 이동하고 있다.
- GitHub Copilot은 코드 작성뿐 아니라 코드 리뷰, 시크릿 탐지, 브라우저 사용, 원격·클라우드 샌드박스까지 개발 루프 전체를 에이전트화하고 있다.
- 공개 벤치마크가 늘어날수록 점수 자체보다 실제 저장소에서의 성공률, 재시도율, 토큰 비용, 보안 오탐률을 측정하는 내부 평가 체계가 중요해진다.
- 모델이 여러 플랫폼과 게이트웨이에 빠르게 배포되는 만큼, 모델 ID·프로바이더·서비스 티어를 설정으로 분리하고 교체 가능한 통합 테스트를 유지해야 한다.
